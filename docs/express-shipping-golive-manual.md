> 写给店主。**从「只会手填单号」到「真机跑通一单预约取件 + 顾客看到轨迹 + 自动完成」，照着这份点。**
> 每个按钮名、每个字段都是从当前代码里核出来的（`apps/admin/src/pages/ShopSettings.tsx`、
> `apps/admin/src/pages/Workbench.tsx`），不是从设计稿抄的。
>
> 参考：`docs/api.md` 附录 G（接口与状态机）、`docs/staff-guide.md` 四点八/四点九（日常操作）、
> `docs/deployment.md`（伪回调演练命令）、`docs/research/2026-09-08-kuaidi100-merchant-shipping-api.md`（报价探测原始数据）。

## 先看这一页：现在卡在哪

技术上代码已合入 `main`，随下一次发布上线（协议层、轨迹、对账都已合入），但离「顾客能真的用」还差六件事，全部只有你或商务/开发能做：

0. **上线前确认生产已执行迁移** `20260913000000_express_bookings` 与 `20260914000000_express_track`（服务器上 `npx prisma migrate status`）——没跑这两条迁移，批次二、三的接口会直接报错。
1. **快递100 商务：上门取件产品已开通**——2026-09-08 用生产 key 探测过，9 家里 **8 家回价**（自贡→成都 1.5 kg 约 ¥6.6–¥17.1）。**顺丰没配价**（返回「当前线路未设置价格」），这不是自贡的问题，换成都寄仍然没价——要找快递100 商务/客户经理问「顺丰上门取件（线上支付）能否开通」，问清楚之前顺丰不能选。
2. **测试环境 key**（邀请制）——伪回调演练、真机跑一单之前最好先申请一套测试环境的 key，不用一上来就在生产账户上试。没有的话联系快递100 商务要邀请码。
3. **服务器 `.env` 三项**：
   - `KD100_EXPRESS_KEY` / `KD100_EXPRESS_SECRET`——快递100 企业账户的 key/secret。
   - `PUBLIC_BASE_URL`——**必须是公网 https 地址**，服务启动时会自检回调地址长度（`/api/kd-express/<单号>/track` 拼出来的完整地址不能超过 200 字节，超了直接拒绝启动），域名太长会启动不了，提前跟开发确认一次。
   - `EXPRESS_PROVIDER_MOCK`——**生产环境必须不设**（留空或不写这一行）。这项一开，下单/查单/结算全部走假数据，顾客付了真钱却拿不到真的取件单。
4. **nginx 已经配好** `location /api/kd-express/`（与 `/api/kd/` 同一份配置：不限流、关 gzip）。部署或换服务器时记得核对一遍：`nginx -T | grep kd-express`，看不到就联系开发补上，不然快递100 的回调会打到不对的 location 上。
5. **后台「邮寄设置」现在是 TABLE 模式**——沿用你之前的旧一口价表，还没有按快递100 实时报价收运费。想按报价收（省钱，因为大部分省内件比旧价便宜）要手动切到 QUOTE，见下面「第四步」。**先跑通一单再切**，别一上来就切。

小程序现在点「全国邮寄」是能下单的（批次一已上线；批次二、三随下一次发布上线），只是运费和取件预约走完整流程之前，先按这份手册确认一遍。

## 这一轮要花多少钱

| 项 | 金额 | 能退吗 |
|---|---|---|
| 查价、下单、查单、轨迹推送 | **免费** | 不涉及 |
| 预约成功那一刻 | **预扣所选家报价**（自贡→成都 1.5 kg 约 **¥6.6–¥17.1**，取决于选哪家快递，见 `docs/research/2026-09-08-kuaidi100-merchant-shipping-api.md` §8.1） | 取件前取消预约 → 全额退回预扣 |
| 快递员上门称重后 | 按实际重量结算，**多退少补**（结算价高于预扣多扣、低于预扣退差额） | 已按实际结算 |
| 已取件后再取消 | 可能产生**逆向物流费**（东西已经在快递公司系统里跑了） | 需联系快递公司处理 |

**一单的净支出大约是那一家的报价本身**，跟同城骑手费不是一回事——这是快递公司的运费，不是平台加价。

余额是从快递100 企业账户扣的；这笔余额跟同城配送共用的账户是不是同一个、额度怎么算，需要找商务确认一次，别假设是分开的。

## 第一步：后台「邮寄设置」

后台左侧栏「邮寄设置」页（`apps/admin/src/pages/ShopSettings.tsx`），这几格与本轮直接相关：

| 字段 | 界面上写的 | 干什么 | 默认值 |
|---|---|---|---|
| `packagingG` | 「每单包装附加重量（克）」 | 每单在商品净重上额外加的包装重（泡沫箱/冰袋实称一次）；寄礼盒、易碎品建议调高 | 800 g |
| `pricingPool` | 「参与定价的快递」勾选区 | 查价、算中位数只看勾中的几家；EMS 折后比标准价还贵、德邦超 2.5 kg 不报价，**默认不勾这两家**。QUOTE 模式下这个勾选只影响顾客付多少，店员发货时仍能看到全部家的价 | 默认勾中极兔/圆通/申通/韵达/中通/京东共 6 家 |
| 地区分组 | 「地区分组」区块 | 一个省只能属于一个组；勾了组里的「不寄送」，顾客选到该地址会被提示暂不支持邮寄 | 见「其他」组兜底 |
| `acceptGraceMin` | 「接单后顾客可申请取消（分钟）」 | 顾客接单后这么多分钟内可以申请取消，0 = 关闭；同意即全额退款 | 10 分钟 |

**不在这个页面上的两件事，容易被误以为能改**：预约弹窗里预填的备注文字（代码里叫 `pickup.defaultRemark`）、无人接单/未取件两条提醒的等待时长（`unacceptedRemindHours` 默认 4 小时、`unpickedRemindMin` 默认 60 分钟），现在都是服务端写死的默认值，后台设置页没有对应的输入框——想改这几项要找开发改（后台设置接口 `PUT /api/admin/settings/express` 或代码），不是自己在页面上调。货物名固定写「食品」，预约弹窗里也不能改。

保存后刷新页面，确认每一格都回显成你刚存的值——这个页面的保存是**整包覆盖**，改之前把每格都看一眼。

## 第三步：真机跑一单

按顺序来，每一步都拍张截图留证。

**3.1 顾客下单**——用你自己的手机，真微信支付，填一个四川以外的地址（省内寄送本来就常用，用外省地址能同时验证「全国」这两个字）。结算页留意运费数字，跟第四步切 QUOTE 之后要对比。

**3.2 后台接单**——工作台「待接单」列，卡片点开右侧抽屉，点「接单」。这一步不产生任何费用。

**3.3 工作台「预约取件」**——「备餐中」列点卡片，点「预约取件」，弹窗里：各家报价**最便宜的默认选中**；重量可以改（改了会重新查价）；时段手选（预填最近可约的时段，顺丰必须填时段）；底部会写清楚「向快递100 下单，预扣 ¥X，快递员上门后按实际重量多退少补」。点「确认预约」。

**3.4 等快递员接单**——卡片会显示「快递员已接单 · 姓名」，出现「打给快递员」按钮，可以直接打电话确认。

**3.5 取件**——快递员上门取件后，订单自动变「已发货」，顾客的微信会收到一条发货通知（跟同城/邮寄手填单号是同一条订阅消息模板）。

**3.6 看轨迹**——快递100 把运输轨迹推给我们之后：顾客小程序订单详情能看到「物流轨迹」（最新一条在最上面）；你在工作台抽屉的「取件预约」块能看到「最新轨迹」一行。这一步不用你操作，也没有按钮要点。

**3.7 签收**——顾客收到货、快递100 推「已签收」轨迹后，订单自动变「已完成」，不需要顾客点「确认收货」，也不需要你点任何按钮。签收这一步**不会**再给顾客发通知（已经收到货了，没必要再提醒）。

**3.8 核对成本行**——工作台订单详情能看到预扣/实扣/计费重三个数字，跟快递100 企业后台的余额变动对一遍：预扣是下单那一刻扣的，实扣是称重结算后的，两者差额应该正好是快递100 后台余额变动的那部分。

## 第四步：切 QUOTE 模式

**先用真账号把 `batchPrice` 跑通、并且跑过至少一单真实预约之后，再切。** 不要在没验证过报价接口能正常回价之前就切，切早了顾客结算页可能查不到价、直接兜底成默认表。

切法：后台「邮寄设置」页，「运费口径」下拉从「只用分组兜底表」（`TABLE`）改成「按快递100 实时报价取中位数（推荐）」（`QUOTE`），保存。切了之后运费算法变成：顾客填完地址那一刻向快递100 查参与定价名单里几家的价，取**中位数** + 「额外加价（元）」（`markupFen`，默认 0）+ 按「向上取整到（元）」取整（`roundToFen`，默认 0.5 元）；查不到价才退回用地区分组里的兜底表。

1. 把第三步、第四步跑的测试单标成 `isTest`（`docs/ops-test-orders.md` 有现成的 curl 命令，`PATCH /api/admin/orders/<ORDER_ID>/test-flag`）。**打标记之前先确认这单该验的都验完了**——`isTest` 的单不发积分，打早了后续想再验证积分相关行为就验不到了。

## 附：提醒都长什么样、收到该做什么

以下提醒都走店员通知渠道（PushPlus），每单每类默认只发一次，收到后不需要在后台改任何设置，照「怎么办」那栏处理即可：

| 提醒 | 什么时候发 | 怎么办 |
|---|---|---|
| 取件预约超时无人接单 | 预约后 4 小时（`unacceptedRemindHours`）无快递员接单 | 改约、换家重约，或联系快递100 客服 |
| 预约时段已过仍未取件 | 预约时段结束 60 分钟（`unpickedRemindMin`）仍无取件回调 | 联系快递员确认是否已取件；未取请改约或取消后换家重约 |
| 预约时段过后仍无进展 | 上一条系统自动查单（对账任务）也没查到新进展 | 同上；系统已经主动查过一次，仍无结果说明问题不在系统这边 |
| 邮寄单取件后长时间未签收 | 已取件超过 10 天（`pickedDays`）仍无签收回调 | 订单已按 7 天规则自动完成；如顾客反馈没收到货，去快递100 后台或联系快递公司查件 |
| 取件预约失败（揽货失败/下单失败） | 快递100 推「揽货失败」或异步下单失败 | 订单已回到备货中：换一家重约，或改填单号发货 |
| 快递100 取消了取件预约 | 快递100 侧主动取消 | 订单已回到备货中，重新预约或改填单号发货 |
| 快递100 余额不足，邮寄预约失败 | 下单时账户余额不够 | 去快递100 企业后台充值 |
| 邮寄实扣运费明显高于预扣 | 结算价 / 预扣 > 告警比例 | 可能是「每单包装附加重量」设低了，去邮寄设置核对重量项 |
| 快递100 轨迹订阅中止 | 轨迹推送里 `status=abort` | 单号可能有误或已超期，顾客端将看不到后续轨迹，去快递100 后台核对单号 |
| 快递100 轨迹显示退签/退回 | 轨迹状态码为退签(4)/退回(6)/拒签(14) | 联系快递员或顾客处理 |
| 作废的预约仍在推状态 | 已作废的预约又收到快递100 回调 | 快递100 那边可能真有单，先核对是否已经产生两张单，不要重复预约 |
| 取件预约状态长时间未确认 / 已停止自动查单 | 「待核对」状态查了 10 次 / 累计 30 次仍无结果 | 打开快递100 后台按订单号核对：没有这张单就点「作废预约」重新预约；有单就等系统自动查到或等快递员电话；拿不准打客服问清楚，不要靠猜 |
