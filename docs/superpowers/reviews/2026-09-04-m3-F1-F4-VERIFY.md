## F1 残留缺口（Critical 同类，未修）

`scheduleQuote()` 的作废是对的，但它挂在链路的末端：

```
点「+」 → _cartMutating=true → PATCH /cart/items/:id （服务端购物车此刻已改）
        → GET /cart → reloadCart 的 .then → setData(subtotal) → scheduleQuote() → 此时才 quoting=true
```

从服务端提交购物车写入、到客户端处理完 `GET /cart` 响应之间（4G 下实测量级 200–800ms，与原来的 500ms debounce 窗口相当），页面状态是：`quoting === false`、`quoteToken` 仍是旧小计签发的那张、按钮文案 `提交订单 ¥旧金额` 且可点。`_cartMutating` 只挡住了后续的 +/−，没有挡提交按钮。此时提交，`onSubmit` 四个守卫全过 → 服务端 `routes/orders.ts:234` 按**新小计**重算，`q.fee <= quoted.fee` 时不报 42227，订单按新金额落库 —— 与 C1 的失败场景完全一致，只是窗口更窄。

**建议补丁**（约 9 行，跨 2 个调用点，超出「顺手补」的额度，交由你决定是否合入）：

```js
  // confirm.js，新增
  invalidateQuote: function() {
    // 购物车一开始改就作废旧票：写入与 reloadCart 的两趟往返里，按钮不能还写着旧金额。
    this._quoteSeq = (this._quoteSeq || 0) + 1
    this.setData({ quoting: true, quoteToken: null })
  },

  updateQuantity: function(id, quantity) {
    var self = this
    this._cartMutating = true
    this.invalidateQuote()                                   // ← 新增
    updateCartItem(id, { quantity: quantity })
      .then(function() { return self.reloadCart() })
      .then(function() { self._cartMutating = false })
      .catch(function() { self._cartMutating = false; self.refreshQuote('retry') })   // ← 失败时必须解除 quoting，否则按钮永久卡在「计算运费中…」
  },
```

`onDelete` 的确认分支同理（删商品会让小计变小、运费可能变贵，虽有 42227 兜底，但展示不一致同样存在）。

## 次要观察（不影响 F1–F4 判定，未修）

1. `address/list.wxml:30` 的距离标签 `wx:if` 只判 `channel === 'LOCAL'`。`/local/meta` 失败或门店无坐标时 `item.localDistanceText` 为 `undefined`，仍会渲染一个带底色圆角内边距的**空胶囊**（`list.wxss:87-95`）。F3 验收写的是「只是没有标签」，严格说不成立。一行可修：`wx:if="{{channel === 'LOCAL' && item.localDistanceText}}"`。
2. `detail.js:383-408`：`startCourierPoll()` 里立即执行的那次 `tick()` 会再打一次 `GET /orders/:id`，而它总是紧跟在 `loadOrder` 自己的详情请求之后（`:327` 在 `.then` 里调 `startCourierPoll`）。于是每次进页面 / `onShow` / 下拉刷新 / 支付取消后刷新，都多一次重复详情请求。无死循环（tick 内不再调 `startCourierPoll`），只是浪费。可让首次 tick 跳过订单刷新。
3. F4 验收文里写的 `POST /admin/system/delivery-mock` 在代码里不存在；实际路径是 `POST /api/admin/system/kd100-mock/*`（`routes/admin/index.ts:37`），推状态要走签名回调，现成脚手架见 `scripts/e2e.sh:748` 的 `kd_cb`。手工验收时照 `kd_cb "$DNO" "$TASKID" 520 '已送达' '<time>'` 用。
