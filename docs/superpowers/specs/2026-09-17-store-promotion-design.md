# 全店自动满减 + 优惠进度提示 设计

日期：2026-09-17　作者：Claude（00 规划前置设计）　状态：待店主审阅

## 0. 一句话

后台可配的**全店自动满减**（多档、按渠道、可设起止时间），顾客不用领券、达标自动减；顾客端在门店头下加一条活动条、在购物车条上加一行「再买 ¥X 减 ¥Y / 免运费」进度提示；结算页金额明细多一行「满减」。

## 1. 已拍板的产品决策（改动需重新确认）

| # | 决策 | 结论 |
|---|---|---|
| P1 | 形式 | **全店自动满减**，不用领券。不做单品折扣（以后再说） |
| P2 | 档位 | **数量不限、后台自己加**（店主 2026-09-17 定）。命中时取**满足条件里力度最大的一档**，不叠加多档 |
| P3 | 生效渠道 | 同城外送 / 到店自取 / 全国邮寄，**三个渠道各自开关，后台勾选**。店主明确：邮寄也要参加，但要能自己开关 |
| P4 | 活动时间 | 可设起止时间，也可长期有效（不填结束时间）。后台可随时停用 |
| P5 | 与优惠券 | **可叠加**。顺序：先满减，再用券抵扣剩下的金额 |
| P6 | 与自取折扣 | 同一单**可同时享受**自取 9.5 折与满减（若自取渠道勾选参加）。三者封顶见 §4.3 |
| P7 | 门槛口径 | 起送门槛、免运费门槛一律按**减前的商品小计**判。现有代码天然如此（`calcLocalFee` 与起送校验用的都是券前、折扣前的 `totalAmount`），本批不改这一点 |
| P8 | 退款 | **按实付金额退**，满减优惠不返还；部分退款不重算满减 |
| P9 | 商品卡标签 | **本批不启用**。满减是「店」的属性，逐道菜打标既无信息量也不好看（美团 2025-06 已取消列表页满减标签）。标签位与样式（菜名下方描边）留给以后的单品活动 |
| P10 | 运费与打包费 | **不参与满减**。满减只减商品金额 |

## 2. 对标

- **美团外卖满减**：多档设计，第一档门槛低拉下单、第二档拉客单价、第三档防拆单；商家后台自助配置档位与生效时段。
- **美团 2025-06 调整**：首页商家列表取消「满减」「折扣菜」标签，改展示评价类信息，理由是反对低质低价内卷——这正是 P9「不逐菜打标」的依据。
- 我们的差异：不做「满减与折扣菜互斥」那套（我们没有单品折扣）；自取折扣是我们特有的，需要额外定义封顶规则（§4.3）。
- 说明：形态层面的一般观察，未逐一截图比对。

## 3. 数据模型

### 3.1 活动配置：放设置，不建新表

沿用项目既有的「设置走 JSON + 60 秒缓存」模式（`services/local-settings.ts`），在店铺设置里新增 `promotion` 块：

```jsonc
{
  "enabled": true,
  "name": "全店满减",
  "startAt": "2026-09-18T00:00:00+08:00",   // 可空 = 立即生效
  "endAt": null,                             // 可空 = 长期有效
  "channels": { "LOCAL_DELIVERY": true, "PICKUP": false, "EXPRESS": true },
  "tiers": [ { "minFen": 5000, "cutFen": 500 }, { "minFen": 10000, "cutFen": 1200 } ]
}
```

**零新表、零建模迁移**；校验规则：`tiers` 按 `minFen` 升序去重，`cutFen < minFen`（否则可白送），最多 10 档。

### 3.2 订单快照：加一列（一次迁移）

| 表.列 | 类型 | 含义 |
|---|---|---|
| `orders.promo_discount_amount` | `INT NOT NULL DEFAULT 0` | 本单实际减掉的满减金额（分）。0 = 没参加/未达标 |

只加列、有默认值、不回填，老订单显示为 0（不显示满减行）。快照字段与 `pickup_discount_amount`、`discount_amount` 同级，退款、对账、小票都按已有习惯读这一列。

**命中的档位**不单独存字段，需要时从金额反推或看运营日志——避免为一行展示再加一列。

## 4. 服务端

### 4.1 计算函数（纯函数，可单测）

`services/promotion.ts`：

```ts
promoDiscountOf(settings, subtotalFen, channelKey, now): number
```
- 活动未启用 / 不在起止时间内 / 该渠道未勾选 → 返回 0
- 否则取所有 `subtotalFen >= minFen` 的档里 `cutFen` 最大的一档（P2）
- `subtotalFen` 用**商品小计**（赠品行 `subtotal=0` 本就不计入，与现有门槛口径一致）

### 4.2 下单链路的插入位置（`routes/orders.ts`）

现有顺序（读代码确认）：`totalAmount`（商品小计）→ 自取折扣 `pickupDiscountOf` → 券（封顶 `totalAmount - pickupDiscount`）→ 运费 `calcLocalFee(s, distanceM, totalAmount, …)` → `computeCheckout({ subtotal, discount, shippingFee, pickupDiscount, packingFee })`。

满减插在**自取折扣之后、券之前**：

1. `promoDiscount = promoDiscountOf(...)`
2. 券的封顶改为 `totalAmount - pickupDiscount - promoDiscount`
3. `computeCheckout` 增加 `promoDiscount` 入参，实付 = 小计 − 自取折扣 − 满减 − 券 + 运费 + 打包费
4. 起送与免运费判定**保持用 `totalAmount`**（P7 天然成立，不动）

### 4.3 封顶规则（必须钉死）

`pickupDiscount + promoDiscount + couponDiscount ≤ totalAmount`（商品小计）。即三者相加不得把商品金额减成负数；券在最后计算，已有封顶参数，只需把 `promoDiscount` 一并扣掉。运费与打包费**永远照收**（P10），所以实付不会为 0。

### 4.4 顾客端要用到的两个只读接口

- 商品列表/门店信息里带上**当前活动**（档位、是否本渠道生效），供活动条显示。跟 `local/meta` 同一批返回，避免多一次请求。
- 结算/报价预览里返回 `promoDiscountFen` 与 `nextTierGapFen`（还差多少到下一档），供购物车条与结算页显示。

### 4.5 退款（P8）

`services/refund.ts` 不改计算：退款一律按**实付金额**为上限，满减不返还、部分退款不重算满减。小票与订单详情按已有习惯多印一行「满减 −¥X」。

## 5. 后台

店铺设置新增「营销 · 满减活动」页：启用开关、活动名称、起止时间、档位表（增删改，显示「满 ¥X 减 ¥Y」）、三个渠道勾选框（自取旁提示「自取已有 9.5 折，叠加后请重算利润」）。保存即生效（设置缓存 60 秒，写操作主动清）。

## 6. 小程序

| 位置 | 内容 |
|---|---|
| 分类页门店头下方 | **活动条**：「满减 满 50 减 5 · 满 100 减 12」+「详情 ›」展开看全部档位与「与优惠券可叠加」 |
| 购物车条上方 | **进度提示**三态：未达标「再买 ¥8 减 ¥5」→ 已达满减未到免运费「已减 ¥5 · 再买 ¥29 免运费」→ 都达成「已减 ¥5 · 已免运费」 |
| 结算页金额明细 | 在「打包费」与「优惠券」之间插一行「满减 −¥5.00」（复用 `sum-cut` 红色样式） |
| 订单详情 / 小票 | 多一行「满减 −¥X」，与优惠券行同级 |
| 商品卡 | **不打标**（P9） |

## 7. 验收

### A. 可脚本化
| 命令 | 期望 |
|---|---|
| `npx tsx apps/server/scripts/selftest-promotion.ts`（新增） | 档位取最大、未达标为 0、停用/过期/渠道未勾为 0、封顶不把商品减成负、赠品行不计入门槛 |
| `npx tsc --noEmit -p apps/server/tsconfig.json` / `npm run build:admin` / `npm test --workspace=apps/admin` | 通过 |
| e2e 新增分片 | 同城/自取/邮寄各下一单验证金额；活动停用后立刻不减；部分退款后订单金额不变 |
| `npm run -s test:miniapp` | 进度提示三态与活动条的纯函数用例全绿 |

### B. 手工
1. 后台配两档、只勾同城外送 → 同城下单达标自动减、自取下单不减。
2. 满减 + 券同时使用，实付 = 小计 − 满减 − 券 + 运费 + 打包费。
3. 点了 52 元（满 50 减 5）→ 起送与免运费仍按 52 判（P7）。
4. 活动设一个已过期的结束时间 → 顾客端活动条消失、下单不再减。
5. 部分退款后订单详情里满减行不变、退款金额不含满减。

## 8. 风险与预案

| 风险 | 预案 |
|---|---|
| 顾客在结算页停留时活动到期 | 下单时服务端**重算**满减（以下单时刻为准），前端显示的金额若与服务端不一致，按既有「报价被篡改」同一套处理：回到结算页提示金额已更新 |
| 自取叠加满减导致亏本 | 自取渠道**默认不勾**，后台勾选处直接写提示；上线后店主自行决定 |
| 档位配错（减得比门槛还多） | 后台保存时校验 `cutFen < minFen`，并提示「这样配会亏本」 |
| 老版本小程序看不到满减行 | 服务端照常计算与落库；旧版只是不显示那一行，金额仍正确 |
| 与积分赠品行冲突 | 赠品行 `subtotal=0`，本就不进门槛与小计，无需特殊处理（沿用既有规则） |

## 9. 上线顺序

1. **服务端 + 后台一批**（含一次迁移）：部署后活动可配、可生效；老版本小程序也能享受到减免，只是不显示明细行。
2. **小程序一批**（活动条 / 进度提示 / 金额行）：合 main → 体验版 → 提审。
3. 两批都不依赖对方先完成；建议先上服务端，店主可以先配好活动、观察数据。
