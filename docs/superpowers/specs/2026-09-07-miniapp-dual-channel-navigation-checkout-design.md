# 小程序双渠道导航与同城结算整改设计

**日期：** 2026-09-07

**状态：** 待店主预览确认

**范围：** 微信小程序顾客端；必要的最小服务端契约补强

**不包含：** 管理后台改版、生产部署、真实运力下单、运费参数调整

## 1. 目标

让“全国邮寄”和“同城配送”拥有相同的四栏主导航与一致的页面骨架，同时保持商品、购物车、结算和订单接口按渠道严格隔离。以同城结算页为核心，补齐新增/选择地址、地图定位、配送报价、优惠券、积分赠品、金额明细、下单、支付、配送追踪、取消退款和售后状态，避免旧金额提交、跨渠道购物车、重复下单和页面溢出。

## 2. 已确认的产品决策

1. 四栏主导航固定为“主页、分类、购物车、我的”，两种渠道的图标、顺序、高度、选中态完全一致。
2. 四栏导航只出现在四个主页面。结算、地址、优惠券弹层、订单详情等流程页不显示四栏导航。
3. 同城页顶部“我的订单”入口删除，由底部“我的”统一承接。
4. 营业状态胶囊紧跟门店名靠左；不再用 `space-between` 把它推开，也不允许绿色背景越界。
5. 同城购物车结算条可在主页/分类页有货时出现，但必须位于原生 tabBar 上方，不能遮挡四栏导航。
6. 全国邮寄与同城配送购物车、角标、结算路径互相隔离，不合并件数。
7. 结算页以地址、配送报价、优惠、金额和提交状态为主，不为追求“看起来简洁”隐藏必要信息。
8. 本阶段先交付独立预览并取得店主确认；确认前不修改业务代码、不部署。
9. 报价失败时底部主按钮可点，点击执行重新报价（见 §5.3）。

## 3. 导航架构

微信原生 tabBar 的 `pagePath` 是固定的，不能为两个渠道各配置四个页面。因此采用“四个共享 tab 页面 + 渠道上下文”的结构：

```text
封面
├─ 全国邮寄 → channel=EXPRESS → 主页/分类/购物车/我的
└─ 同城配送 → channel=LOCAL   → 主页/分类/购物车/我的
```

渠道上下文保存为 `EXPRESS | LOCAL`：

- 内存中的 `app.globalData.shoppingChannel` 是当前会话的权威值；
- storage 只用于页面重载/开发者工具热重载后的恢复；
- 封面每次选择渠道时显式覆盖；
- 切换 tab 不改变渠道；
- 商品、分类、购物车和订单请求必须显式传渠道，不依赖服务端默认值；
- 旧的 `/pages/local/index` 保留为兼容入口，只负责切换到 `LOCAL` 并转入共享主页，避免旧链接失效。

## 4. 四个主页面

| 页面 | 全国邮寄 | 同城配送 |
|---|---|---|
| 主页 | 现有 Banner、分类、推荐商品 | 门店信息、营业状态、配送规则、同城推荐与快捷分类 |
| 分类 | 搜索、左分类、右商品，进入商品详情 | 左分类、右商品，直接加同城购物车；多规格弹 SKU |
| 购物车 | `EXPRESS` 购物车，进入邮寄结算 | `LOCAL` 购物车，显示起送提示并进入同城结算 |
| 我的 | 共用账号、会员、地址、协议 | 页面骨架相同；订单入口默认带当前渠道，仍可切换“全部” |

### 4.1 同城页头

第一行仅包含门店图标、门店名、营业状态：

```text
[门店图标] 阿福凉菜 [营业中]
```

- 行使用左对齐；门店名允许省略，状态胶囊不可压缩；
- 胶囊使用 `inline-flex`、单行、内容自适应和 `box-sizing:border-box`；
- 营业中为浅绿底/深绿字，暂停接单为浅橙底/橙字，已打烊为浅灰底/灰字；
- 第二行展示配送范围、起送价和基础运费；
- 第三行仅在暂停、打烊等异常状态出现，并提供“改用全国邮寄”；
- 原“我的订单 ›”删除。

## 5. 同城结算页

### 5.1 页面顺序

1. 页面级营业/暂停通知；
2. 收货地址卡；
3. 配送报价卡；
4. 商品明细；
5. 优惠券与积分赠品；
6. 餐具与订单备注；
7. 金额明细；
8. 协议提示；
9. 固定的应付金额与提交按钮。

页面主体滚动，固定栏不覆盖最后一张卡；小屏、安全区和备注输入法弹出时仍能看到当前输入区域。

### 5.2 地址卡状态

| 状态 | 展示 | 主操作 |
|---|---|---|
| 无地址 | “新增收货地址”与说明 | 新增地址 |
| 地址完整 | 姓名、脱敏电话、POI、完整门牌 | 更换地址 |
| 缺定位 | 橙色提示“需要补充地图定位” | 补充定位 |
| 定位已过期 | 地址文字变更提示 | 重新选点 |
| 报价超范围 | 距离与超范围原因 | 换地址 / 全国邮寄 |

从结算页新增地址，保存后直接返回结算页并自动选中新地址。切换地址的第一瞬间作废旧报价、旧总价和旧 `quoteToken`，新报价返回前禁止提交。

### 5.3 配送报价状态

| 状态 | 页面表现 | 提交状态 |
|---|---|---|
| 等待地址 | “选择地址后计算配送费” | 禁用 |
| 计算中 | 骨架/加载文案 | 禁用 |
| 成功 | 距离、实测/估算标识、配送费、预计分钟与时间 | 继续判断 |
| 网络失败 | 明确错误与“重新获取运费” | 底部主按钮变为**可点的重新报价**（见下） |
| 限流 | “操作频繁，请稍后重试” | 禁用并延迟重试一次 |
| 报价过期 | 自动重新报价，金额显示待计算 | 禁用 |
| 未达起送 | 显示还差金额 | 禁用 |
| 暂停/打烊/超范围 | 显示原因和替代路径 | 禁用 |

报价过期时间由服务端随报价返回，客户端不再硬编码 10 分钟；服务端仍保留签名与 15 分钟有效期的最终判断。

**报价失败时底部主按钮的行为（店主 2026-09-07 拍板，方案 B）**：按钮**可点**，文案“重新获取运费”，
点击后重新报价而不是提交订单。取的是“手指不用离开底部”这个便利；代价是同一屏上会有两个
功能相同的按钮（配送信息卡里那个小按钮保留）。

因此按钮状态判定的返回值必须携带 `action`（`submit | retry | none`），页面按 `action` 分派点击，
**不允许以“按钮未禁用”推断应当提交**——报价失败时没有有效的 `quoteToken`，
那样提交会被服务端 42239 拒掉，顾客只会看到一句莫名其妙的报错。

### 5.4 优惠券与积分赠品

- 优惠券行显示“可用张数”或已选券名称与抵扣金额；
- 选券使用最大高度约 70vh 的底部弹层，包含安全区；
- “不使用优惠券”始终可选；
- 可用券排前，不可用券置灰并显示原因；
- 券只抵商品金额，不抵配送费；起送与免运仍按券前小计；
- 积分当前只兑换赠品，不作为现金抵扣；
- 赠品显示图片、规格、积分、库存和数量；
- 优惠接口失败时明确说明“可原价下单”，不阻塞主流程；
- 提交时若券、积分、库存发生并发冲突，刷新优惠与金额后要求顾客再次确认。

### 5.5 金额明细

结算页新增独立金额卡，固定口径：

```text
商品金额   ¥48.00
优惠券     -¥5.00
配送费      ¥6.00
积分赠品    300积分
应付金额   ¥49.00
```

底部栏只展示应付金额和短按钮文案。暂停、超范围、未达起送等长原因显示在上方提示区，不能塞进按钮造成溢出。

### 5.6 提交防线

- 地址、数量、优惠或赠品一变，旧提交条件立即失效；
- 页面内 `_submitting` 防双击；
- 每次结算生成 `clientRequestId`，相同请求重试由服务端返回同一订单，解决“服务端已创建但客户端超时”导致的重复订单；
- 成功创建后立即清除本次 request id，跳转订单详情并按现有逻辑拉起支付；
- 42227/42239 重新报价；42201 刷新商品；42251/42252 刷新优惠；营业/范围错误刷新 meta 与报价；
- 不在任何失败状态保留可点击的旧金额按钮。

## 6. 地址新增与选择

### 6.1 地址列表

- LOCAL 模式展示默认标记、直线粗估距离、缺定位和可能超范围提示；
- 道路距离与实际运费仍只在结算页计算，避免逐地址外呼；
- 地址列表自身必须在 `/local/meta` 失败时继续展示；
- 选择完整地址后立即返回结算页；缺定位地址进入编辑页；
- 空列表固定提供“新增收货地址”。

### 6.2 地址编辑

- 地图选点是 LOCAL 必填；
- 导入微信地址只填联系人和文字，不冒充坐标；
- 修改省市区、详细地址或再次导入后，旧坐标标记为待确认；
- 顾客取消地图选择不修改原地址；权限拒绝提供可见引导；
- 匿名坐标报价走统一的 API 包装层，失败只隐藏报价条，不弹全局 toast；
- 保存按钮有在途保护，成功后向上游回传新/改地址。

## 7. 购物车与角标

- `getCart` 总是显式传 `EXPRESS` 或 `LOCAL`；
- tabBar 角标只统计当前渠道；切换渠道立即刷新；
- 同城购物车显示商品、规格、数量、库存、券前小计和起送差额；
- 数量变化立刻刷新当前渠道角标；
- 同城结算只提交 LOCAL 购物车项；服务端继续做渠道一致性校验；
- 页面为空时“去逛逛”进入当前渠道分类，而不是固定进入全国邮寄主页。

## 8. 我的订单与订单后链路

- 顶部“我的订单”删除；
- “我的”页订单入口默认传当前渠道，订单列表提供“当前渠道/全部”切换；
- 服务端订单列表新增可选 `deliveryType` 过滤，避免客户端分页后过滤造成漏单；
- 订单卡继续显示“同城/邮寄”标签；
- 同城订单详情保留配送距离、预计送达、配送费、骑手、位置、取消、退款和售后；
- 订单进入终态后停止骑手轮询；页面隐藏/卸载时停止定时器；
- LOCAL 不显示“确认收货”，以配送回调/店员送达为准。

## 9. 接口契约

| 接口 | 整改要求 |
|---|---|
| `GET /categories` | 客户端始终显式传 `channel` |
| `GET /products` | 客户端始终显式传 `channel` |
| `GET /cart` | 客户端始终显式传 `channel` |
| `POST /local/quote` | 返回 `quoteExpiresAt`；地址编辑匿名报价走统一封装 |
| `GET /member/checkout-options` | 继续传渠道和券前小计 |
| `POST /orders` | 接收 `clientRequestId` 并保证同用户幂等 |
| `GET /orders` | 新增可选 `deliveryType=EXPRESS|LOCAL` |

金额、距离、优惠资格和最终库存继续以服务端为准，客户端只负责展示与失效状态控制。

## 10. 预览与验收矩阵

实施前的独立预览至少包含：

1. 同城主页正常营业；
2. 暂停接单与已打烊；
3. 分类页与有货购物车条；
4. LOCAL 购物车空态/有货态；
5. 结算页正常态；
6. 无地址、缺定位、超范围；
7. 报价中、报价失败、报价过期；
8. 优惠券弹层：可用、不可用、未选择；
9. 积分赠品不足与库存不足；
10. 未达起送、提交中、提交失败；
11. 小屏手机、安全区、长门店名、长地址、最大字号；
12. 全国邮寄四栏页面回归，确认没有被 LOCAL 状态污染。

自动化覆盖纯状态机、渠道隔离、查询参数、金额展示、旧报价失效、幂等下单和订单过滤；微信开发者工具覆盖导航、弹层、键盘、安全区和真实组件渲染；真机覆盖隐私授权、地图选点、支付取消/成功与骑手轮询停止。

## 11. 发布边界

本设计和下一份实施计划本身不授权修改业务代码、部署或发布。执行顺序必须是：独立预览 → 店主确认 → 实现与自动化验证 → 开发者工具预览 → 店主再次确认 → 另行授权部署。
