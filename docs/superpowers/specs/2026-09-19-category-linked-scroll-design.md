# 分类页整页联动滚动设计

## 用户已确认的目标

用户截图中购物栏遮住左侧末尾分类（酒水/饮料），且店铺头部占据较大空间。用户已认可“先整页上移，再滚动商品”的联动方向，并明确授权制作规划、Agent 分工执行及审核。实现范围是现有分类页的交互改造。

1. 初始展示完整店铺信息、营业提示、活动说明。
2. 上滑右侧商品区时，头部随页面自然上移；同城外送/自取切换栏吸顶，随后继续浏览商品。
3. 反向浏览商品时，头部保持收起；商品回到页面前部后，继续下拉自然露出头部。不对每次反向滑动执行自动展开动画。
4. 左侧分类独立滚动；选中分类随右侧商品变化，必要时自动进入可视区域。最后一个分类、商品及加购按钮必须可以完整看到并点击。
5. 底部优惠提示和购物栏固定；有/无商品、提示变化、屏幕变化都按实测高度调节可视空间。
6. 邮寄保留搜索与渠道入口，搜索分页/清除、首页分类定位、同城模式切换与购物车计价继续有效。

## 技术方案

现有页面为 WebView，`.page` 的 `100vh + overflow:hidden` 限制页面滚动，左右为独立 `scroll-view`；右侧有购物栏占位而左侧没有。采用一个原生页面滚动承载头部与右侧商品；左侧保留一个独立 `scroll-view`。不用触摸拦截模拟惯性、不迁移 Skyline、不增加运行依赖。

页面结构：同城店铺头（可滚离）/同城活动条（可滚离）→ 同城模式栏（sticky top:0）→ 左侧分类和右侧普通商品容器。邮寄搜索/渠道入口固定吸顶，活动条与搜索标签可滚离；具体节点顺序以避免 sticky 父容器过早结束为准。右侧当前分类标题保持可读，可使用各分组标题原生 sticky，避免出现两份重叠标题。

所有 sticky 元素的祖先不得设置阻碍页面滚动的 overflow/固定高度。左侧外壳使用 sticky 或按页面位置计算的固定布局；顶部为当前两栏区在屏幕的位置（不高于吸顶栏底部），高度为剩余视口减去实测购物栏高度。仅在头部收起区间改变侧栏高度，不在整段商品滚动持续 setData 大对象。

记录布局变量：视口高度 V（原生 tabBar 上方的 windowHeight）、吸顶工具栏高 P、两栏起点文档坐标 B、购物栏整体占用 D、当前页面滚动 Y。侧栏顶部 `max(P, B-Y)`，侧栏可视高 `max(0,V-D-max(P,B-Y))`。右侧分组锚点为文档坐标，定位到 `max(0,groupTop-P)`。高亮按 `Y+P` 查询分组，保留点击动画期短暂锁定和尾随节流。

最后分组补白 `max(0,V-P-D-lastGroupHeight)`；页面末尾另保留且仅保留一份 D 占位，两者用途不同。这样短分组也可定位到吸顶栏下，并且末件商品高于购物栏。当前 `.cart-dock` 已是全宽不透明背景，直接作为右侧内容的底部遮挡边界，不另叠遮罩；保留其层级，商品通过页面末尾 D 留白可完整滚到栏上方。

数据返回、店铺通知变化、模式/渠道切换、购物栏 height 事件、onShow、onResize 后重量；隐藏/卸载废弃旧测量回调和清理定时器。测量从 selector 的 viewport scrollOffset 读取文档滚动位置；不得把不同时刻的旧滚动值与新 bounding rect 混用。渠道切换清理旧定位、锁、偏移与搜索状态，防止异步旧结果覆盖新渠道。普通同渠道 onShow 保持位置；头部已收起时，异步头部/活动高度变化按文档坐标差补偿页面滚动，避免正在看的商品跳位。搜索首批内容不足一屏且 hasMore 时允许继续加载，不能只等不会发生的触底事件。

侧栏自动定位只在目标条目位于当前侧栏可视范围之外时触发，不因每个右侧 scroll 事件强制回中打断手动找分类。类别 ID 包含数值与 `other`，生成合法带前缀 DOM id。页面定位使用 `wx.pageScrollTo`，同分类重复点击也应生效；用户交互打断动画时不能永久锁住高亮。

## 全局约束

- 只修改分类页、分类滚动专用工具/测试、预览镜像、该任务文档；不修改服务端、管理后台、支付、运费、满减计算或共享购物栏行为。
- 同城免运费继续使用现有后台动态配置，任何布局改动不得硬编码门槛。
- 保持 WebView 渲染及原生 tabBar；不引入 Skyline、新运行依赖或 npm install。
- 新增小程序逻辑文件为 ES5/CommonJS；既有文件新增逻辑使用 var/function，避免扩大语法兼容范围。
- 购物栏高度以 height 事件的实测整体值为准；为 0 时完整恢复空间；不硬编码设备高度、安全区或 tabBar 高度。
- 旧测试可随明确改变的滚动契约更新，必须用新的行为断言替代，不能删测试或跳过失败；与本次无关的计价/渠道测试保持语义。
- 浏览器镜像只能证明布局与模拟交互；微信真机惯性、原生 tabBar、安全区及触摸体验必须如实列为真机验收，不能用镜像通过代替。

## 验收与边界

必须自动验证坐标/补白计算、最后分类可见、同分类反复定位、搜索分页/清空、切渠道时在途回调隔离、窗口与购物栏变化、隐藏后不再写布局、无商品/仅一个短分组/分类很多/负滚动回弹。浏览器需包含同城初始、收起、末分类、空车/有车、320/375/430 宽与邮寄搜索场景，留截图和几何测量。

真机步骤：iOS 与 Android 各进入同城 → 加购 → 上滑头部 → 浏览末分类 → 反向滑至顶部 → 左侧独立滑动 → 切自取/外送 → 清空购物车 → 邮寄搜索/返回。核验滑动连续、点击加购有效、栏与原生 tabBar 无缝、商品及分类不穿透购物栏、返回分类页位置合理。
