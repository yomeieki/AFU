# 商城管理后台业务中心化改造设计

日期：2026-09-07

状态：方案已确认，待实现

范围：`apps/admin` 前端信息架构、导航、页面组合与本地预览；不修改业务规则，不部署生产

## 1. 背景与目标

当前商城后台已经具备接单、商品、分类、邮寄订单、同城订单、优惠券、积分赠品、会员设置和配送设置等实际操作页面。现有问题不在功能缺失，而在于功能增加后仍全部平铺在左侧导航：入口数量多、同一业务域被拆散、渠道层级和功能层级混在一起。

本次改造把后台重组为四个业务中心，并把接单工作台提升为最高优先级入口：

1. 接单工作台独立置顶。
2. 商品列表和分类管理合并为“商品管理”。
3. 同城订单和邮寄订单合并为“订单管理”。
4. 优惠券、积分赠品和会员设置合并为“会员营销”。
5. 全国邮寄设置和同城设置合并为“店铺设置”。
6. 保留已有数据接口、业务规则、危险操作确认和工作台交互。
7. 完成后只启动本地预览，不执行部署、数据库迁移或生产配置变更。

## 2. 已确认的设计决策

| 决策 | 结论 |
|---|---|
| 总体模式 | 使用“单行顶部主导航 + 页面内分级页签 + 更多下拉菜单”，完全移除左侧栏 |
| 品牌区域 | 顶部左侧只保留用户提供的红色方形 Logo；不显示任何品牌文字，点击回到经营概览 |
| 接单工作台 | 保持独立全屏路由，作为顶部 Logo 后的第一个强调入口 |
| 页面合并方式 | 建立业务中心外壳，原业务组件作为子页面；不合并成单个超大组件 |
| 状态来源 | 路由负责一级页面和渠道，查询参数负责状态、筛选和页码 |
| 兼容性 | 旧地址保留重定向，已有书签和代码跳转继续可用 |
| 数据层 | 继续使用现有 API；本轮不要求服务端接口改造 |
| 发布方式 | 构建通过后启动本地预览并打开浏览器；不部署 |

## 3. 现状约束

- `/workbench` 当前位于鉴权内、通用 `Layout` 外，是独立全屏接单界面。该边界正确，继续保留。
- 商品和分类页面都已支持 `EXPRESS`、`LOCAL` 渠道切换；合并后不能丢失渠道隔离。
- 邮寄订单和同城订单的状态机、操作按钮及 API 不同，只统一入口和外壳，不强行共用业务操作。
- 优惠券页面包含模板管理和发放记录分页；会员设置依赖优惠券模板状态；二者合并后仍须保持实时健康提示和链接联动。
- 同城设置包含门店位置、配送计价、营业时段、履约参数和运力配置，信息量远大于全国邮寄设置；两个设置页必须分别保存。
- 现有页面已实现移动端卡片表格、接口失败态和部分自动刷新逻辑，改造不能退化这些能力。

## 4. 一级导航设计

顶部固定为一行。主导航只保留高频入口：

| 顺序 | 入口 | 目标路由 | 说明 |
|---:|---|---|---|
| 1 | Logo | `/dashboard` | 只显示小 Logo，无品牌文字 |
| 2 | 接单工作台 | `/workbench` | 独立强调按钮，显示总待处理数 |
| 3 | 经营概览 | `/dashboard` | 保留现有概览 |
| 4 | 订单管理 | `/orders/local` | 同城与全国邮寄合并，默认进入同城历史单 |
| 5 | 商品管理 | `/catalog/products` | 商品列表与分类管理合并 |
| 6 | 更多 | — | 承载低频业务入口，详见下文 |

“更多”按以下分组展示，点击子项直接进入对应路由：

| 分组 | 子项 |
|---|---|
| 会员营销 | 会员管理、优惠券、积分赠品 |
| 店铺设置 | 全国邮寄设置、同城设置 |
| 后台工具 | 用户管理、扫码统计、轮播管理、打印机设置、系统状态 |

### 4.1 接单工作台入口

接单工作台从普通导航项升级为顶部 Logo 后的独立主入口：

- 与普通导航留出视觉间距，使用实色或浅色强调背景。
- 显示同城待接单、邮寄待处理和售后待处理的聚合数字；数量超过 99 显示 `99+`。
- 当前位于工作台时仍保持选中状态，但工作台本身继续使用现有全屏布局。
- 不把“经营概览”放到工作台之上。

## 5. 通用业务中心外壳

新增统一的业务中心页面外壳，负责以下内容：

- 页面标题和简短说明。
- 一级功能页签。
- 可选的二级渠道或状态导航区域。
- 右上角当前子页面的主要操作按钮。
- 移动端横向滚动页签和紧凑页头。

外壳只负责页面结构和路由，不负责加载具体业务数据。商品、订单、会员和设置页面继续各自维护请求、错误态、保存态和弹窗，避免一个业务失败导致整个中心不可用。

页面层级固定为：

```text
顶部一级入口 / 更多菜单
└── 业务中心页头
    ├── 一级功能页签
    └── 二级渠道 / 状态 / 筛选
        └── 原业务内容区
```

## 6. 商品管理中心

### 6.1 页面层级

一级功能页签：

- 商品列表
- 分类管理

二级渠道页签：

- 全国邮寄
- 同城配送

最终层级：`商品管理 → 商品列表/分类管理 → 全国邮寄/同城配送`。

### 6.2 交互规则

- 从商品列表切换到分类管理时保留当前渠道。
- 从分类管理切换回商品列表时保留当前渠道。
- 商品筛选中的分类只显示当前渠道的分类。
- 新增商品默认使用当前渠道，新建/编辑时只能选择当前渠道下的分类。
- 编辑已有分类并变更渠道时，继续显示现有的商品迁移和购物车清理风险提示。
- 商品列表和分类列表分别保留自己的搜索、筛选、分页或滚动位置；互相切换不串状态。

### 6.3 路由

- `/catalog/products?channel=EXPRESS`
- `/catalog/categories?channel=EXPRESS`
- `channel` 仅接受 `EXPRESS` 或 `LOCAL`，无效值回退到 `EXPRESS`。

现有 `Products`、`Categories` 组件拆除重复标题和重复渠道页签后嵌入商品中心；表格、弹窗和保存逻辑不合并。

## 7. 订单管理中心

### 7.1 页面层级

一级渠道页签：

- 同城配送
- 全国邮寄

二级状态页签随渠道变化。

同城配送状态：

- 全部
- 待接单
- 备餐中
- 配送中
- 已完成
- 已退款

全国邮寄状态：

- 全部
- 待付款
- 待接单
- 备餐中
- 已发货
- 已完成
- 已取消
- 退款
- 售后

最终层级：`订单管理 → 配送渠道 → 订单状态`。

### 7.2 交互规则

- 同城和邮寄分别通过各自 URL 表达当前状态页签。
- 切换渠道后默认进入该渠道的“全部”状态，不套用另一个渠道不存在的状态。
- 搜索词、页码和状态写入 URL，刷新后保持当前位置。
- 两个渠道继续调用各自现有 API，保留各自的自动刷新、详情展开、退款、售后、发货、骑手和打印操作。
- 订单中心左侧导航徽标显示全部待处理数量；渠道页签分别显示各自待处理数。
- 接单工作台仍然是高频接单入口，订单中心定位为查询、售后和完整管理，不复制工作台看板。

### 7.3 路由

- `/orders/local?status=...&page=...&keyword=...`
- `/orders/express?status=...&page=...&keyword=...`

`LocalOrders` 和 `Orders` 保持独立子组件。共享的仅是页面页头、渠道页签、URL 状态解析和通用加载提示样式。

## 8. 会员营销中心

### 8.1 一级功能页签

- 优惠券
- 积分赠品
- 会员设置

最终层级：`会员营销 → 业务功能 → 功能内部筛选/分区`。

### 8.2 优惠券

- 保留来源、渠道和启用状态筛选。
- 来源展示使用中文主名称，技术枚举只作为次要说明，不直接以 `ADMIN`、`POINTS` 等英文作为主标签。
- 模板列表使用分页；发放记录继续使用独立分页，两个页码互不影响。
- 新客券健康状态和“正在被会员设置使用”标识保留。

### 8.3 积分赠品

- 增加全国邮寄/同城配送渠道筛选。
- 增加启用状态和关联商品状态筛选。
- 列表按 20 条一页进行前端分页；本轮继续使用现有一次性列表 API，不扩大到服务端改造。
- 新增/编辑、上下架、删除和商品/SKU 选择逻辑保持不变。

### 8.4 会员设置

会员设置不是列表，不进行形式化分页；页面内分为三个清晰区块：

1. 积分发放规则。
2. 新客券配置与健康状态。
3. 会员规则说明。

会员设置中跳转优惠券管理的链接改为 `/membership/coupons`，并尽量携带新客券来源筛选。

### 8.5 路由

- `/membership/coupons?page=...&source=...&channel=...&status=...`
- `/membership/points-goods?page=...&channel=...&status=...`
- `/membership/settings`

## 9. 店铺设置中心

### 9.1 一级页签

- 全国邮寄设置
- 同城配送设置

最终层级：`店铺设置 → 配送方式 → 设置分区`。

### 9.2 全国邮寄设置

保留现有固定运费、满额包邮、起送金额和实时试算。页面名称从泛化的“店铺设置”明确为“全国邮寄设置”。

### 9.3 同城配送设置

保留以下分区：

- 营业状态和暂停接单。
- 门店名称、电话、地址与坐标。
- 配送范围、基础运费、阶梯加价、包邮和起送金额。
- 营业时段、备餐时间和履约限制。
- 运力策略和小费限制。

### 9.4 保存和离开保护

- 两个设置子页各自加载和保存，绝不合并提交。
- 页面有未保存修改时，点击另一设置页签或其他后台导航先弹出离开确认。
- 保存成功后清除未保存标记；保存失败时停留当前页并显示现有服务端错误信息。
- 浏览器刷新和关闭保护作为增强项；如果浏览器限制自定义文案，使用浏览器标准提示。

### 9.5 路由

- `/settings/express`
- `/settings/local`

## 10. 路由迁移和旧地址兼容

旧路由继续接收访问，并使用 `replace` 重定向到新路由：

| 旧地址 | 新地址 |
|---|---|
| `/products` | `/catalog/products` |
| `/categories` | `/catalog/categories` |
| `/orders` | `/orders/express` |
| `/local/orders` | `/orders/local` |
| `/coupons` | `/membership/coupons` |
| `/points-goods` | `/membership/points-goods` |
| `/member-settings` | `/membership/settings` |
| `/shop-settings` | `/settings/express` |
| `/local/settings` | `/settings/local` |

重定向必须保留原查询参数。例如 `/orders?status=PAID` 应到达 `/orders/express?status=PAID`。通知铃铛、订单提醒和会员设置内部链接直接改用新地址，不依赖重定向作为长期逻辑。

## 11. 状态与数据流

### 11.1 路由状态

- 当前业务中心和一级页签由路径决定。
- 渠道、订单状态、筛选条件和页码由查询参数决定。
- 查询参数先经过白名单解析，无效值使用默认值，避免错误 URL 造成空页面。
- 对会影响数据请求的查询参数使用 `replace` 更新，避免浏览器历史中产生大量无意义记录；跨业务页签使用普通导航，允许返回。

### 11.2 页面状态

- 弹窗开关、编辑表单、保存中状态和接口错误继续由具体业务页面维护。
- 父级业务中心不持有商品、订单、券或设置数据。
- 页面切换后允许子组件卸载，避免隐藏页面持续轮询订单或保留过期表单。
- 必须保留的筛选状态写进 URL，不依赖组件常驻。

### 11.3 加载与错误

- 子页面加载失败时只替换自己的内容区，业务中心页签仍可操作。
- 自动刷新失败继续保留旧数据并显示“数据可能不是最新”的提示。
- 明确区分“空列表”和“加载失败”，不把接口异常显示成没有数据。
- 合并页面不改变服务端错误文案；订单和设置中的可操作错误继续原样展示给店员。

## 12. 组件边界

计划新增或调整的前端边界：

- `Layout`：新一级导航、置顶工作台入口、聚合徽标。
- `BusinessCenterLayout`：通用页头与一级页签。
- `CatalogCenter`：商品/分类路由外壳与渠道同步。
- `OrderCenter`：同城/邮寄路由外壳与状态导航。
- `MembershipCenter`：优惠券/积分赠品/会员设置路由外壳。
- `ShopSettingsCenter`：全国邮寄/同城设置路由外壳与离开保护接口。
- `LegacyRedirect`：保留查询参数的旧地址重定向。

原业务组件只做嵌入所需的最小调整，例如移除重复页面标题、从父级读取渠道或通过 URL 读取筛选。不得在本次改造中重写订单状态机、商品保存载荷、会员规则或配送计价。

## 13. 视觉与响应式要求

- 沿用现有品牌橙红色，不重新定义品牌资产。
- 一级业务页签比筛选控件更突出；二级状态页签使用较轻的下划线或胶囊样式。
- 页面标题、页签、筛选区、数据区之间使用统一间距。
- 顶部始终只显示一行，左侧栏和移动端抽屉均不保留。
- 小屏幕仍保留全部主导航入口，但按钮隐藏文字、显示图标和 `aria-label`；不能出现横向滚动。
- “更多”弹层按业务分组，键盘焦点与 `aria-expanded` 状态必须可用。
- 表格已有的移动卡片视图继续保留。
- 接单工作台的日夜主题和全屏模式不纳入常规后台主题改造。

## 14. 验收标准

### 14.1 导航和路由

- 登录后只出现单行顶部导航；没有左侧栏。
- 接单工作台是 Logo 后的最高优先级业务入口。
- 会员营销、店铺设置和后台工具均位于“更多”分组菜单。
- 左侧不再分别出现商品/分类、同城/邮寄订单、优惠券/积分赠品/会员设置、两类配送设置。
- 四个业务中心内的所有子页可通过页签到达。
- 旧地址和通知跳转正确到达新页面，并保留查询参数。
- 刷新任一深层地址后仍停留在同一子页、渠道、状态和页码。

### 14.2 业务回归

- 商品和分类渠道不会串线；新增商品只能选择对应渠道分类。
- 同城和邮寄订单分别加载正确数据，原有操作按钮和确认逻辑可用。
- 优惠券模板、发放记录、积分赠品和会员规则均能独立操作。
- 全国邮寄和同城设置分别保存；有未保存内容时切换受到保护。
- 接单工作台不受通用布局和路由调整影响。

### 14.3 质量与预览

- TypeScript 检查和 Vite 生产构建通过。
- 桌面宽屏、普通笔记本和移动窄屏各检查一次导航和页签。
- 检查空数据、加载失败、长列表分页和待处理徽标四类状态。
- 构建完成后启动本地 Vite 预览，并在浏览器中打开供用户验收。
- 不运行部署脚本，不提交生产服务器，不改域名或线上环境变量。
