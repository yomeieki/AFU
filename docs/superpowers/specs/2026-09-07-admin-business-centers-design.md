# 商城管理后台业务中心化改造设计

日期：2026-09-07

状态：方案已口头确认，等待文档复核

范围：`apps/admin` 前端信息架构、导航、页面组合与本地预览；不修改业务规则，不部署生产

修订：2026-09-07 第二轮。店主定稿三项变更——① 一级导航从左侧栏改为顶部单行；② 品牌区去掉
「阿福凉菜」文字与餐具图标，只留印章 Logo；③ 轮播管理 + 扫码统计合并为「推广运营」，打印机
设置 + 系统状态合并为「系统维护」。第 4、10、11、12、15、16、17 节按此重写或新增。

## 1. 背景与目标

当前商城后台已经具备接单、商品、分类、邮寄订单、同城订单、优惠券、积分赠品、会员设置和配送设置等实际操作页面。现有问题不在功能缺失，而在于功能增加后仍全部平铺在左侧导航：入口数量多、同一业务域被拆散、渠道层级和功能层级混在一起。

本次改造把后台重组为六个业务中心、一级导航移到页面顶部，并把接单工作台提升为最高优先级入口：

1. 接单工作台独立置顶。
2. 商品列表和分类管理合并为“商品管理”。
3. 同城订单和邮寄订单合并为“订单管理”。
4. 优惠券、积分赠品和会员设置合并为“会员营销”。
5. 全国邮寄设置和同城设置合并为“店铺设置”。
6. 轮播管理和扫码统计合并为“推广运营”。
7. 打印机设置和系统状态合并为“系统维护”。
8. 一级导航由左侧栏改为顶部单行，品牌区只保留印章 Logo。
9. 保留已有数据接口、业务规则、危险操作确认和工作台交互。
10. 完成后只启动本地预览，不执行部署、数据库迁移或生产配置变更。

## 2. 已确认的设计决策

| 决策 | 结论 |
|---|---|
| 总体模式 | 使用“顶部一级业务入口 + 页面内分级页签”，不使用多层折叠菜单，也不使用“更多”下拉 |
| 接单工作台 | 保持独立全屏路由，作为顶栏第一个、唯一实色强调的入口 |
| 页面合并方式 | 建立业务中心外壳，原业务组件作为子页面；不合并成单个超大组件 |
| 状态来源 | 路由负责一级页面和渠道，查询参数负责状态、筛选和页码 |
| 兼容性 | 旧地址保留重定向，已有书签和代码跳转继续可用 |
| 数据层 | 继续使用现有 API；本轮不要求服务端接口改造 |
| 发布方式 | 构建通过后启动本地预览并打开浏览器；不部署 |

## 3. 现状约束

- `/workbench` 当前位于鉴权内、通用 `Layout` 外，是独立全屏接单界面。该边界正确，继续保留。
- 商品和分类页面都已支持 `EXPRESS`、`LOCAL` 渠道切换；合并后不能丢失渠道隔离。
- 邮寄订单和同城订单的状态机、操作按钮及 API 不同，只统一入口和外壳，不强行共用业务操作。
- 优惠券页面包含模板管理和发放记录分页；会员设置依赖优惠券模板状态；二者合并后仍须保持实时健康提示和链接联动。
- 同城设置包含门店位置、配送计价、营业时段、履约参数和运力配置，信息量远大于全国邮寄设置；两个设置页必须分别保存。
- 现有页面已实现移动端卡片表格、接口失败态和部分自动刷新逻辑，改造不能退化这些能力。

## 4. 一级导航设计

一级导航位于页面顶部单行，不再使用左侧栏。两处合并后入口降到 9 个，可以全部平铺展开，
因此**不设「更多」下拉菜单**——低频入口藏进二级菜单会让它们变成两次点击，而 9 个入口的
宽度在一行里放得下。

| 顺序 | 入口 | 目标路由 | 说明 |
|---:|---|---|---|
| 1 | 接单工作台 | `/workbench` | 独立强调按钮，显示同城待接单数 |
| 2 | 经营概览 | `/dashboard` | 保留现有概览 |
| 3 | 商品管理 | `/catalog/products` | 商品列表与分类管理合并 |
| 4 | 订单管理 | `/orders/local` | 同城与全国邮寄合并，默认进入同城历史单 |
| 5 | 会员营销 | `/membership/coupons` | 优惠券、积分赠品、会员设置合并 |
| 6 | 店铺设置 | `/settings/express` | 全国邮寄与同城设置合并 |
| 7 | 用户管理 | `/users` | 保留 |
| 8 | 推广运营 | `/promotion/banners` | 轮播图与扫码统计合并（本轮新增） |
| 9 | 系统维护 | `/system/printer` | 打印机设置与系统状态合并（本轮新增） |

### 4.1 接单工作台入口

接单工作台是顶栏第一个入口，且是唯一使用实色强调背景的项：

- 与其余 8 项之间留出视觉间距，靠底色而非仅靠位置区分。
- 徽标只显示**同城待接单数**（`localPendingCount`）。
- 当前位于工作台时保持选中态，工作台本身继续使用现有全屏布局。
- 图标用 `LayoutGrid`，与「订单管理」的 `ClipboardList` 必须是两个不同图标。

### 4.2 徽标口径（修正既有缺陷）

改造前 `orderBadge = pendingCount + afterSaleCount + localPendingCount` 这一个数同时挂在
「接单工作台」和「订单管理」两处，两边显示同一个数字，看不出该点哪个。本轮拆开：

| 入口 | 徽标数值 | tooltip |
|---|---|---|
| 接单工作台 | `localPendingCount` | `同城待接单 N` |
| 订单管理 | `pendingCount + afterSaleCount` | `待处理 N · 售后 N` |

两者都在超过 99 时显示 `99+`。

### 4.3 响应式三档

顶部导航按可用宽度分三档退化，**任何一档都不允许一级导航横向滚动**：

断点取值来自实测，不是估计。9 个中文标签一行所需的最小视口宽度（含 Logo、
右侧按钮与内边距）：纯文字 **878px**，带图标 **1134px**。据此取：

| 断点 | 形态 |
|---|---|
| ≥ 1200px | 图标 + 文字，右侧「退出登录」带文字，一行 9 项 |
| 960–1199px | 去掉图标与「退出登录」文字，把宽度让给导航项，仍是一行 9 项 |
| < 960px | 顶栏收成「Logo + 当前页名 + ⌄ + 铃铛 + 退出图标」，点击从顶部落下 3×3 九宫格面板 |

注意 960 这条线把平板竖屏（768–959）也划进了九宫格。这是刻意的：那个宽度
放不下 9 个四字标签，而九宫格在平板上一屏看全 9 个，比切掉一项或改用「更多」
下拉都好。

窄屏选九宫格而不是横滑页签：横滑需要盲滑找入口，九宫格一屏看全 9 个、一次点击到达，
且符合「从上方点」的操作方向。面板规则：

- 每格显示图标 + 文字 + 徽标，最小点击区 44×44 px。
- 点任一格立即跳转并收起面板；点遮罩或按 Esc 也收起。
- 面板展开时锁定背景滚动。
- 存在未保存设置时，收起前先走 `confirmLeave`，与桌面档一致。

### 4.4 品牌区

- 去掉「阿福凉菜」文字和 `UtensilsCrossed` 餐具图标。
- 只保留印章 Logo（`/brand-logo.png`），高 32px、`object-contain`，点击回 `/dashboard`。
- Logo 需提供 `alt="阿福凉菜"`，文字被移除后它是唯一的品牌可访问名。
- 顶栏总高 56px（原侧栏版页头为 64px）。

## 5. 通用业务中心外壳

新增统一的业务中心页面外壳，负责以下内容：

- 页面标题和简短说明。
- 一级功能页签。
- 可选的二级渠道或状态导航区域。
- 右上角当前子页面的主要操作按钮。
- 移动端横向滚动页签和紧凑页头。

外壳只负责页面结构和路由，不负责加载具体业务数据。商品、订单、会员和设置页面继续各自维护请求、错误态、保存态和弹窗，避免一个业务失败导致整个中心不可用。

页面层级固定为：

```text
顶部一级入口
└── 业务中心页头
    ├── 一级功能页签
    └── 二级渠道 / 状态 / 筛选
        └── 原业务内容区
```

## 6. 商品管理中心

### 6.1 页面层级

一级功能页签：

- 商品列表
- 分类管理

二级渠道页签：

- 全国邮寄
- 同城配送

最终层级：`商品管理 → 商品列表/分类管理 → 全国邮寄/同城配送`。

### 6.2 交互规则

- 从商品列表切换到分类管理时保留当前渠道。
- 从分类管理切换回商品列表时保留当前渠道。
- 商品筛选中的分类只显示当前渠道的分类。
- 新增商品默认使用当前渠道，新建/编辑时只能选择当前渠道下的分类。
- 编辑已有分类并变更渠道时，继续显示现有的商品迁移和购物车清理风险提示。
- 商品列表和分类列表分别保留自己的搜索、筛选、分页或滚动位置；互相切换不串状态。

### 6.3 路由

- `/catalog/products?channel=EXPRESS`
- `/catalog/categories?channel=EXPRESS`
- `channel` 仅接受 `EXPRESS` 或 `LOCAL`，无效值回退到 `EXPRESS`。

现有 `Products`、`Categories` 组件拆除重复标题和重复渠道页签后嵌入商品中心；表格、弹窗和保存逻辑不合并。

## 7. 订单管理中心

### 7.1 页面层级

一级渠道页签：

- 同城配送
- 全国邮寄

二级状态页签随渠道变化。

同城配送状态：

- 全部
- 待接单
- 备餐中
- 配送中
- 已完成
- 已退款

全国邮寄状态：

- 全部
- 待付款
- 待接单
- 备餐中
- 已发货
- 已完成
- 已取消
- 退款
- 售后

最终层级：`订单管理 → 配送渠道 → 订单状态`。

### 7.2 交互规则

- 同城和邮寄分别通过各自 URL 表达当前状态页签。
- 切换渠道后默认进入该渠道的“全部”状态，不套用另一个渠道不存在的状态。
- 搜索词、页码和状态写入 URL，刷新后保持当前位置。
- 两个渠道继续调用各自现有 API，保留各自的自动刷新、详情展开、退款、售后、发货、骑手和打印操作。
- 订单中心的顶栏徽标显示「待处理 + 售后」（同城待接单归接单工作台，见 §4.2）；渠道页签分别显示各自待处理数。
- 接单工作台仍然是高频接单入口，订单中心定位为查询、售后和完整管理，不复制工作台看板。

### 7.3 路由

- `/orders/local?status=...&page=...&keyword=...`
- `/orders/express?status=...&page=...&keyword=...`

`LocalOrders` 和 `Orders` 保持独立子组件。共享的仅是页面页头、渠道页签、URL 状态解析和通用加载提示样式。

## 8. 会员营销中心

### 8.1 一级功能页签

- 优惠券
- 积分赠品
- 会员设置

最终层级：`会员营销 → 业务功能 → 功能内部筛选/分区`。

### 8.2 优惠券

- 保留来源、渠道和启用状态筛选。
- 来源展示使用中文主名称，技术枚举只作为次要说明，不直接以 `ADMIN`、`POINTS` 等英文作为主标签。
- 模板列表使用分页；发放记录继续使用独立分页，两个页码互不影响。
- 新客券健康状态和“正在被会员设置使用”标识保留。

### 8.3 积分赠品

- 增加全国邮寄/同城配送渠道筛选。
- 增加启用状态和关联商品状态筛选。
- 列表按 20 条一页进行前端分页；本轮继续使用现有一次性列表 API，不扩大到服务端改造。
- 新增/编辑、上下架、删除和商品/SKU 选择逻辑保持不变。

### 8.4 会员设置

会员设置不是列表，不进行形式化分页；页面内分为三个清晰区块：

1. 积分发放规则。
2. 新客券配置与健康状态。
3. 会员规则说明。

会员设置中跳转优惠券管理的链接改为 `/membership/coupons`，并尽量携带新客券来源筛选。

### 8.5 路由

- `/membership/coupons?page=...&source=...&channel=...&status=...`
- `/membership/points-goods?page=...&channel=...&status=...`
- `/membership/settings`

## 9. 店铺设置中心

### 9.1 一级页签

- 全国邮寄设置
- 同城配送设置

最终层级：`店铺设置 → 配送方式 → 设置分区`。

### 9.2 全国邮寄设置

保留现有固定运费、满额包邮、起送金额和实时试算。页面名称从泛化的“店铺设置”明确为“全国邮寄设置”。

### 9.3 同城配送设置

保留以下分区：

- 营业状态和暂停接单。
- 门店名称、电话、地址与坐标。
- 配送范围、基础运费、阶梯加价、包邮和起送金额。
- 营业时段、备餐时间和履约限制。
- 运力策略和小费限制。

### 9.4 保存和离开保护

- 两个设置子页各自加载和保存，绝不合并提交。
- 页面有未保存修改时，点击另一设置页签或其他后台导航先弹出离开确认。
- 保存成功后清除未保存标记；保存失败时停留当前页并显示现有服务端错误信息。
- 浏览器刷新和关闭保护作为增强项；如果浏览器限制自定义文案，使用浏览器标准提示。

### 9.5 路由

- `/settings/express`
- `/settings/local`

## 10. 推广运营中心

轮播图和扫码统计合并为一个中心：两者都是「拉客」侧的配置与效果——轮播图是顾客打开小程序
第一眼的门面，扫码统计是包装二维码带来的复购数据。与「会员营销」的区别是后者管的是券和
积分等**权益规则**，本中心管的是**曝光位与曝光效果**。

### 10.1 页面层级

```text
顶部入口「推广运营」
└── 中心页头
    ├── 页签：轮播图 / 扫码统计
    └── 原 Banners.tsx / ScanStats.tsx 内容区
```

### 10.2 交互规则

- 复用 §5 的 `BusinessCenter` 外壳与 `centerTabs` 数据，不新增机制。
- 两个子页各自保留原有的加载态、失败态和移动端卡片视图。
- 轮播图的新增/编辑弹窗与扫码统计的趋势图均不改动。
- 页签顺序为「轮播图」在前：它是配置项，改完才看得到扫码效果。

### 10.3 路由

| 路由 | 页面 |
|---|---|
| `/promotion` | 重定向到 `/promotion/banners` |
| `/promotion/banners` | 轮播图管理 |
| `/promotion/scan-stats` | 扫码统计 |

## 11. 系统维护中心

经常连着走：小票没出 → 先看打印机在不在线 → 再看系统状态里的服务端配置。

### 11.1 页面层级

```text
顶部入口「系统维护」
└── 中心页头
    ├── 页签：打印机 / 系统状态
    └── 原 PrinterSettings.tsx / SystemStatus.tsx 内容区
```

### 11.2 交互规则

- 复用 §5 的 `BusinessCenter` 外壳。
- 页签顺序为「打印机」在前并作为默认子页：店员真正会点进来的几乎总是打印机那一页。
- 打印机的测试打印、切纸补白等危险或耗材操作保持原有确认逻辑。
- 系统状态页继续只读展示布尔项，不因合并而获得写能力。

### 11.3 路由

| 路由 | 页面 |
|---|---|
| `/system` | 重定向到 `/system/printer` |
| `/system/printer` | 打印机设置 |

## 13. 状态与数据流

### 11.1 路由状态

- 当前业务中心和一级页签由路径决定。
- 渠道、订单状态、筛选条件和页码由查询参数决定。
- 查询参数先经过白名单解析，无效值使用默认值，避免错误 URL 造成空页面。
- 对会影响数据请求的查询参数使用 `replace` 更新，避免浏览器历史中产生大量无意义记录；跨业务页签使用普通导航，允许返回。

### 11.2 页面状态

- 弹窗开关、编辑表单、保存中状态和接口错误继续由具体业务页面维护。
- 父级业务中心不持有商品、订单、券或设置数据。
- 页面切换后允许子组件卸载，避免隐藏页面持续轮询订单或保留过期表单。
- 必须保留的筛选状态写进 URL，不依赖组件常驻。

### 11.3 加载与错误

- 子页面加载失败时只替换自己的内容区，业务中心页签仍可操作。
- 自动刷新失败继续保留旧数据并显示“数据可能不是最新”的提示。
- 明确区分“空列表”和“加载失败”，不把接口异常显示成没有数据。
- 合并页面不改变服务端错误文案；订单和设置中的可操作错误继续原样展示给店员。

## 14. 组件边界

计划新增或调整的前端边界：

- `Layout`：新一级导航、置顶工作台入口、聚合徽标。
- `BusinessCenterLayout`：通用页头与一级页签。
- `CatalogCenter`：商品/分类路由外壳与渠道同步。
- `OrderCenter`：同城/邮寄路由外壳与状态导航。
- `MembershipCenter`：优惠券/积分赠品/会员设置路由外壳。
- `ShopSettingsCenter`：全国邮寄/同城设置路由外壳与离开保护接口。
- `LegacyRedirect`：保留查询参数的旧地址重定向。

原业务组件只做嵌入所需的最小调整，例如移除重复页面标题、从父级读取渠道或通过 URL 读取筛选。不得在本次改造中重写订单状态机、商品保存载荷、会员规则或配送计价。
