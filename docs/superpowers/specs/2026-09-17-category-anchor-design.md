# 分类页左右联动（分组锚点）设计

日期：2026-09-17　作者：Claude（00 规划前置设计）　状态：待店主审阅

## 0. 一句话

分类页右侧不再翻页，而是一次拉全本渠道的菜、按分类分段展示；左边点分类滚到对应段，右边滑动时左边高亮跟着走。**同城与全国邮寄都改**，邮寄的搜索保留。

## 1. 已拍板的产品决策（改动需重新确认）

| # | 决策 | 结论 |
|---|---|---|
| C1 | 交互 | 左右联动：点左侧分类 → 右侧滚到该段；右侧滚动 → 左侧高亮跟随（美团/饿了么点餐页那套） |
| C2 | 渠道 | 同城、全国邮寄**都改**，同一套代码 |
| C3 | 「全部」项 | 去掉。左侧第一项就是第一个分类，进页默认停在它上面 |
| C4 | 右侧数据 | 一次拉全（按页循环拉到没有为止，不写死上限），不再「滑到底加载更多」 |
| C5 | 段内顺序 | 由服务端排好，小程序不自己排。默认＝本分类里勾推荐的在前、其余按录入顺序；店主在后台把某分类设成「按销量」或拖拽调整后自动跟着变（见 `2026-09-17-category-product-sort-design.md`） |
| C6 | 空分类 | **照常显示**（店主 2026-09-17 定）。邮寄现有 3 个空分类（礼盒、预包装食品、素食）留在左侧，点它滚到该段，段内显示「该分类暂无商品」一行占位（有占位才滚得过去、高亮才停得住） |
| C7 | 搜索（仅邮寄） | 保留。搜索时右侧切成平铺结果、不分段，左侧不高亮；清掉搜索回到分组视图 |
| C8 | 服务端 | 只加一个字段（列表接口返回分类 id），零迁移 |
| C9 | 不受影响 | 首页、同城门店头 / 外送自取栏 / 购物车条 / 加购弹层、商品详情、扫码入口 |

## 2. 对标

- **美团外卖、饿了么的店内点餐页**：左分类右菜单，分类名吸顶，左右联动，点左侧跳段；没有「全部」这一项。
- **瑞幸、蜜雪一类点单小程序**：同一形态，菜单一次给全，靠滚动而不是翻页。
- 我们的差异：一个页面同时服务同城点餐与全国邮寄零售，所以邮寄那侧在分组之上多一个搜索框（C7）。
- 说明：以上为形态层面的一般观察，未逐一截图比对。

## 3. 数据量（2026-09-17 线上实测）

| 渠道 | 分类（有菜的） | 菜数 |
|---|---|---|
| 同城 | 9 个：特色菜 6、凉菜 27、风味菜 35、鱼 3、素菜 16、炒饭 6、汤 14、酒水饮料 13、白米饭 1 | 121 |
| 邮寄 | 4 个：凉菜 15、冷吃 2、卤味 1、红油 1（另 3 个空分类隐藏） | 19 |

## 4. 服务端（唯一改动）

`apps/server/src/routes/products.ts` 的 `GET /api/products` 在 `select` 里加 `categoryId: true`（与后台排序那批的 `sortOrder` 字段一并加，两批谁先上都行）。

- 不改排序、不改分页、不改任何既有字段，老版本小程序看不见新字段，不受影响。
- 零迁移。可以先单独上线，不必等小程序。

## 5. 小程序

### 5.1 纯函数（可单测，放 `utils/catalog-groups.js`，ES5）

| 函数 | 作用 |
|---|---|
| `groupByCategory(categories, products)` | 按 `categories` 给定顺序分组，返回 `[{ id, name, items }]`；**空分类保留**（`items` 为空数组，页面渲染一行「该分类暂无商品」）；`categoryId` 不在分类表里的菜归到末尾的「其他」段（正常不会有，兜底不丢菜） |
| `activeGroupOf(offsets, scrollTop, tolerance)` | 给定各段顶部位置与当前滚动位置，返回当前应高亮的段 id。判定用「段顶 ≤ scrollTop + 容差」的最后一段 |

单测文件 `tests/miniapp/catalog-groups.test.cjs`：分组顺序、空分类保留且 items 为空、未知分类进「其他」、边界滚动位置（正好在段顶、段间、滚到底）。

### 5.2 页面（`pages/product/list`）

- **拉数据**：进页 / 切渠道时循环调 `getProducts({ channel, page, pageSize: 50 })`，直到 `已拉条数 >= total`，再 `groupByCategory` 得到 `groups`。上限保护：最多 20 页（1000 条）后停下并打日志，防止接口异常时死循环。
- **左侧**：渲染 `groups`（无「全部」）。点击设置 `scrollIntoView = 'g-' + id`，并**立刻**把高亮设成被点的分类。
- **右侧**：`scroll-view` 里按段渲染，每段一个锚点 `<view id="g-{{id}}" class="group-anchor">`，段头显示分类名。
- **吸顶段头**：不用 CSS `position: sticky`（`scroll-view` 内各端表现不一致），改为在右侧顶部覆盖一条「当前分类」浮动条，内容跟着高亮段变。
- **滚动联动**：`bindscroll` 拿 `scrollTop`，与预先量好的 `offsets` 比对，**节流 100ms**。`offsets` 在 `groups` 渲染完后用 `createSelectorQuery().selectAll('.group-anchor').boundingClientRect()` + `.scrollOffset()` 量一次；切渠道、退出搜索、图片首次撑开高度后（`onImageLoad` 去抖 300ms）重量一次。
- **点击与滚动打架**：点左侧后滚动动画进行中，`bindscroll` 会把高亮改成中间经过的分类。做法：点击时记 `lockUntil = Date.now() + 500`，锁定期内忽略滚动事件的高亮计算。
- **最后一段顶不上去**：最后一段之后补一块空白，高度 = 右侧可视高度 − 最后一段高度（不足则为 0），保证最后一个分类能被滚到顶、能被高亮。
- **从首页进来**：`app.globalData.pendingCategoryId` 仍然有效，数据到位后滚到该段（原来的 `applyCategory` 语义改为「定位」）。
- **搜索（邮寄）**：`searchKeyword` 非空时右侧渲染平铺结果、隐藏段头与浮动条、左侧不高亮；清掉搜索回到分组视图并回到顶部。

### 5.3 删掉的东西

`activeCategoryId` 作为**筛选条件**的用法、`ALL_CATEGORY`（左侧「全部」项）。

分页状态（`page` / `hasMore` / `total` / `onScrollToLower`）**保留但只在搜索模式下生效**：邮寄搜索结果可能较多，仍是滑到底加载更多。分组视图下右侧一次拉全，不走分页。

|---|---|

### B. 真机（微信开发者工具 + 店主手机）

1. 同城进分类页：左侧 9 个分类、无「全部」，默认高亮「阿福特色菜」，右侧第一段就是特色菜。
2. 右侧一路滑到底：左侧高亮依次跟到凉菜、风味菜…… 最后能停在「白米饭」。
3. 点左侧「汤」：右侧跳到汤那一段，段头显示「汤」，左侧高亮停在「汤」不乱跳。
4. 邮寄进分类页：左侧 7 项（含礼盒、预包装食品、素食三个空分类），点空分类能滚到该段、段内显示「该分类暂无商品」、左侧高亮停在它上面。
5. 邮寄搜索「兔」：右侧平铺结果、无段头；点 × 清除 → 回到分组视图、回到顶部。
6. 首页点某个分类进来：直接定位到那一段。
7. 同城加购、购物车条、外送/自取切换、门店头一切照旧。
8. 弱网下进页：分批拉取过程中不出现「半截菜单」错觉（拉完再渲染，拉取中显示骨架屏）。

## 7. 风险与预案

| 风险 | 预案 |
|---|---|
| 一次拉全量变慢（以后菜变多） | 分批拉取 + 骨架屏；上限 20 页保护；若日后单渠道超过 300 道，再评估「按段懒加载」 |
| 图片加载后高度变化，锚点位置失准 | 图片首次加载后去抖 300ms 重量一次 `offsets` |
| 滚动事件频繁导致卡顿 | 节流 100ms，滚动时只做数值比较，不做 setData（高亮变化时才 setData） |
| 点左侧后高亮被滚动事件改掉 | 点击锁定 500ms |
| 空分类段太矮，滚过去后高亮停不住 | 空段也给固定高度（占位行 + 内边距），与「最后一段补白」同一套处理 |
| `scroll-into-view` 在某些机型不触发 | 兜底用 `scroll-top` + 量好的 offset 直接定位 |

## 9. 后续维护（店主视角）

- 后台**加分类、加菜、调分类顺序**：小程序自动跟着变，**不用提审**。
- 分类顺序就是左侧从上到下的顺序，由后台「分类管理」的排序值决定。
- 某个分类暂时不想让顾客看到：在后台把分类本身停用（`status`），下架菜不会让分类消失（空分类照常显示）。
