# 需求文档

## 一、项目目标

开发一个微信小程序食品商城系统，将线下实体食品/熟食门店的商品搬到线上，实现用户在小程序内浏览商品、下单、微信付款、填写收货地址、门店后台接单发货的完整交易闭环。

同时支持商品包装上印刷小程序二维码，用户扫描包装二维码后可直接跳转到商品详情页并再次下单，实现线下顾客的线上复购。

## 二、业务背景

- 业态：线下实体食品/熟食门店
- 商品类型：熟食、预包装食品、礼盒
- 核心诉求：线上化销售渠道 + 包装复购入口
- 配送方式：快递发货、同城配送（后续支持到店自提）
- 支付方式：微信支付（第一阶段使用 mock payment）

## 四、暂不开发的功能（明确排除）

以下功能第一版明确不做，后续版本再评估：

| 功能 | 原因 |
|------|------|
| 会员等级 | 复杂度高，MVP 不需要 |
| 积分系统 | 需要单独设计，后续规划 |
| 分销系统 | 涉及合规，后续规划 |
| 拼团 | 复杂营销功能 |
| 秒杀 | 需要高并发设计 |
| 直播带货 | 独立功能模块 |
| 多门店管理 | 目前单店 |
| 复杂优惠券 | 后续规划 |
| 复杂 CRM | 超出 MVP 范围 |
| ERP 对接 | 后续规划 |
| 自动打印小票 | 硬件依赖 |
| 复杂财务报表 | 后续规划 |
| 复杂物流轨迹查询 | 第三方接口对接 |
| 批次级二维码追踪 | 第一版只做商品级 |
| 到店自提 | 订单流程预留，UI 暂不实现 |

## 五、非功能性要求

- 安全：后端计算金额，前端不可传最终价格
- 安全：支付回调验签 + 幂等
- 安全：管理后台强制登录
- 安全：密码 bcrypt hash 存储
- 安全：环境变量管理密钥，不硬编码
- 合规：小程序合法域名使用 HTTPS
- 稳定：数据库定期备份
- 扩展：数据库表预留扩展字段，方便后续升级
