2.4 节的内容分散在好几处(公众平台勾选项、代码里的隐私弹窗、`legal.js` 条款文案),容易出现"某一处改了、其余几处没跟着改"。上线前(以及日后任何改动位置相关代码之后)按下表一次性核对完:

| 检查项 | 怎么核对 | 当前状态(2026-09 核实) |

## 六、常见打回原因与对策

| 打回理由 | 原因 | 对策 |
|---|---|---|
| 类目与内容不符 / 缺少资质 | 食品类目未传许可证或已过期 | 服务类目重新上传证件 |
| 未提供用户协议 / 隐私政策 | 审核员没找到入口 | 补充说明写明路径「我的 → 关于我们」 |
| 隐私保护指引未填写或与实际不符 | 指引未生效、勾选项与代码行为不一致 | 按 2.4 重填,确认「已生效」 |
| 支付功能不可用 | 商户号未配好 / 回调验签失败 | 系统状态页排查,一分钱实测通过后再提 |
| 页面存在无法打开的功能 | 图片 404(COS 域名未配 downloadFile)、接口报错 | 体验版真机全流程走一遍 |
| 未提供客服方式 | — | 补充说明写客服电话;「联系商家」入口截图 |
| 诱导分享 | 分享文案含「分享得奖励」等 | 当前文案无此问题,不要后续加 |
| 名称与类目不符 | 名称含「商城」但类目非电商平台 | 已改名「阿福凉菜」 |
| 商家管理入口需要账号 | 审核员点进「商家管理」被登录页拦住 | 补充说明注明「内部使用可忽略」 |
| 积分商城被判「虚拟支付 / 抽奖 / 变相充值」 | 审核员看到「积分商城」四个字就往虚拟币方向理解 | 补充说明主动写明不涉及提现、充值、抽奖、转让(见 §五 模板);附「会员中心 → 规则说明」页截图。**本店储值方案当初就因个体户资质被否,这条边界要主动说清** |

## 八、回滚预案

| 场景 | 操作 |
|---|---|
| 小程序线上版本有严重问题 | 公众平台 → 版本管理 → 线上版本 → 「版本回退」(可回退到上一个已发布版本) |
| 后端部署出问题 | `DEPLOY_REF=<部署前 sha> bash scripts/deploy.sh`(每次部署结束脚本会打印这条带具体 sha 的命令,直接复制即可)。**不要**先手动 `git reset --hard <上一版>` 再裸跑 `bash scripts/deploy.sh`——脚本第 2 步会无条件 `git reset --hard` 到 `origin/main`(或 `DEPLOY_REF`),手动 reset 会被这一步原样覆盖掉,等于没回滚 |
| 数据库迁移出问题 | deploy.sh 在迁移前自动备份到 `/www/backups/pre-deploy/`,按打印的 `gunzip | mysql` 命令恢复。恢复流程本身已经实测演练过一次(见 `docs/ops-restore-drill.md`:18 张表逐项对齐、金额校验一致、全程未碰生产库),不是纸面流程 |
| 支付/退款回调异常 | 企微告警群会收到「金额不一致」「退款异常」;回调丢失由自动补查兜底,退失败的单在「退款待处理」页签重试,勿直接改数据库 |
