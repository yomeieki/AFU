## ① 订阅消息：新增「配送通知」模板

### 背景
微信规定：一次授权弹窗最多请求 **3 个模板**，且每个模板**一次授权只能发一条**消息。所以按渠道分开请求：

| 渠道 | 顾客下单时请求授权的模板 |
|---|---|
| 同城配送 | **配送通知**（骑手取餐出发时发）+ 退款通知 |
| 全国邮寄 | 发货通知（已有）+ 退款通知（已有） |

所以本次**只需新增 1 个「配送通知」模板**，发货/退款两个沿用现有的。

### 操作步骤
1. 登录 mp.weixin.qq.com → 左侧 **功能 → 订阅消息**
2. 点 **公共模板库** → 搜索框依次试这些词：`配送`、`派送`、`订单配送`、`送达`、`骑手`
3. 挑一个语义最接近「您的订单已由骑手取走，正在配送中」的模板。优先级：
   - 第一优先：模板名含「配送」且关键词里有 **订单编号 / 配送状态 / 预计送达时间**
   - 第二优先：模板名含「订单状态变更」「订单进度」
4. 点「选用」→ 在关键词列表里**按下表勾选**（勾选顺序决定字段编号，不同模板可选项不一样，按有什么勾什么）：

| 想传的内容 | 优先勾这些关键词 | 备选 |
|---|---|---|
| 订单编号 | 订单编号 / 订单号 | 订单信息 |
| 配送方式或状态 | 配送状态 / 订单状态 / 配送方式 | 温馨提示 |
| 骑手或商家联系方式 | 配送员电话 / 联系电话 | 服务电话 |
| 预计送达 | 预计送达时间 / 送达时间 | 配送时间 |

   > 关键词最多勾 5 个，**不够选就少勾**，能拿到「订单编号 + 一个状态类 + 一个时间类」就够用。

5. 「场景说明」填（可直接复制）：

```
顾客在小程序下单同城配送的凉菜后，骑手到店取餐并出发配送时，向该顾客推送本条通知，
告知订单已开始配送及预计送达时间，方便顾客留意收货。仅向本人下单的顾客发送，不做营销推广。
```

6. 提交 → 回到 **我的模板**，把这一条的 **模板 ID** 复制下来
7. 点开该模板，把每个关键词对应的**字段名**抄下来（形如 `character_string1`、`thing2`、`time4`、`phrase3`）

### 需要交给开发的东西
把下面这段填好发给开发（**只有这些，不涉及任何密钥**）：

```
配送通知模板 ID：
字段对应：
  订单编号 = character_string?
  配送状态 = ?
  预计送达 = ?
  （其余按实际填）
```

### 顺便核对（如果之前没做完）
`docs/miniapp-release-checklist.md` 2.6 节里「发货通知」「退款通知」两个模板如果还没配到服务器，一并把模板 ID 和字段名给开发。

## ② 隐私保护指引：新增「收集你选择的位置信息」

### 现状
2026-09-02 已填过一版，勾了：收货地址、手机号、剪贴板。
本次要**新增一项**，因为同城配送要让顾客在地图上选收货位置。

### 操作步骤
1. mp.weixin.qq.com → **设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引** → 点「更新」/「去完善」
2. 在「开发者处理的信息」清单里，找到并**勾选**：

   > **收集你选择的位置信息**

   ⚠️ 注意区分两个相似项，**只勾下面这个**：
   | 选项 | 对应接口 | 我们要不要 |
   |---|---|---|
   | 收集你的位置信息 | `wx.getLocation`（自动读取实时定位） | ❌ **不勾** |
   | **收集你选择的位置信息** | `wx.chooseLocation`（用户自己在地图上点） | ✅ **勾** |

   只勾后者的好处：顾客感受更好（是他自己点的，不是被偷偷定位），接口申请通过率也高得多。

3. 用途说明填（可直接复制）：

```
用于同城配送服务：顾客在填写收货地址时于地图上选择收货位置，
我们据此计算配送距离、判断是否在配送范围内、计算配送费，并将该位置提供给配送服务商用于骑手送达。
```

4. 已勾的其余项保持不变（收货地址、手机号、剪贴板）
5. 「开发者联系方式」确认是 `15309003232` / `835804187@qq.com`
6. 保存提交

### 生效说明
保存后需平台审核（通常当天），状态变「已生效」才算数。**接口申请（③）审核时会看这份指引，所以必须先于③完成。**

### 代码侧配套（开发做，不用您操作）
- 隐私政策全文（小程序「我的 → 关于我们 → 隐私政策」）里新增一条「向第三方配送服务商提供收货信息」的说明——微信的勾选表单里没有这一项，只能写在我们自己的隐私政策里，但**必须写**，否则属于未告知就共享。
- 小程序代码里开启官方隐私弹窗（`__usePrivacyCheck__`），第一次用地图选点时会弹「授权同意隐私协议」。

## ③ 地理位置接口申请（等页面做好后再做）

### 只申请一个接口
**`wx.chooseLocation`（打开地图选择位置）**，不申请 `wx.getLocation`。

原因：`wx.getLocation` 是"自动读取用户实时位置"，微信的开放范围很窄，[社区里连续被驳回八次的案例](https://developers.weixin.qq.com/community/develop/doc/0000c2ead50158047ce1cf6c26b800)基本都是它；官方在驳回时也会主动建议改用 `wx.chooseLocation`。而"顾客自己在地图上点收货位置"是外卖/配送的标准场景，最容易通过。
商家设置门店坐标同样改用地图选点（店主在地图上点自家店），比 GPS 定位更准——室内 GPS 会漂几十米，直接影响所有订单的距离和运费。

### 操作步骤
1. mp.weixin.qq.com → **开发管理 → 接口设置**（有的版本在「开发 → 开发管理 → 接口设置」）
2. 找到「地理位置」相关接口列表，选 **`wx.chooseLocation` 打开地图选择位置**，点「申请」
3. 「申请原因/使用场景」填（可直接复制）：

```
本小程序为自贡市实体凉菜熟食门店「丹桂阿福凉菜」的线上点单小程序，已上传营业执照与食品经营许可证。
现新增同城配送服务：顾客在小程序内选购凉菜后，需要填写收货地址。

由于凉菜属于短保质期即时配送商品，仅靠文字地址无法确定顾客与门店的实际距离，
会出现超出配送范围仍下单、配送费算错、骑手找不到具体楼栋等问题。

因此在「新增收货地址」页面提供「地图选点」功能：顾客点击后调用 wx.chooseLocation 打开地图，
自行选择收货位置并确认。小程序据此：
1. 计算该位置与门店的距离，判断是否在配送范围内（超出范围则提示顾客改选地址或改用全国邮寄）；
2. 按距离计算配送费并在下单前明确展示给顾客；
3. 将该位置提供给第三方即时配送服务商，供骑手导航送达。

位置信息仅在顾客主动点击「地图选点」并确认后获取，不做后台静默定位、不做轨迹追踪、不用于任何营销用途。
已在《用户隐私保护指引》中勾选「收集你选择的位置信息」并说明用途。
```

4. 上传**页面截图**（关键，决定通过率）。需要一组能连起来看懂的图，建议 4 张：
   1. 同城配送菜单页（能看到商品和「配送至…」的地址栏）
   2. 「新增收货地址」表单页，**「地图选点」按钮清晰可见**
   3. 点击后打开的**地图选点界面**
   4. 选完点返回，表单里已回填地址、并显示「距离 x.x km / 配送费 ¥x」的页面

   截图要求：
   - **不能出现「测试」「demo」「假数据」字样**，商品名、价格、地址都用真实的
   - 用手机真机截图或开发者工具模拟器截图都可以，**开发版即可，不需要先发布**
   - 图上可以用红框圈出关键按钮并加文字说明

5. 提交，等 1–3 个工作日

### 被驳回怎么办
驳回信息会说明原因，两类：
- **"无法确认使用场景"** → 截图不够清楚，补一张录屏（从点击按钮到选完点回填的完整过程，10–20 秒）
- **"场景未符合接口开放范围"** → 检查是不是误申请了 `wx.getLocation`；只申请 `chooseLocation` 一般不会遇到

把驳回原文发给开发，一起改申请材料。每次驳回后可以重新提交。
