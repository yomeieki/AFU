## ① 订阅消息：新增「配送通知」模板

### 背景
微信规定：一次授权弹窗最多请求 **3 个模板**，且每个模板**一次授权只能发一条**消息。所以按渠道分开请求：

| 渠道 | 顾客下单时请求授权的模板 |
|---|---|
| 同城配送 | **配送通知**（骑手取餐出发时发）+ 退款通知 |
| 全国邮寄 | 发货通知（已有）+ 退款通知（已有） |

所以本次**只需新增 1 个「配送通知」模板**，发货/退款两个沿用现有的。

### 操作步骤
1. 登录 mp.weixin.qq.com → 左侧 **功能 → 订阅消息**
2. 点 **公共模板库** → 搜索框依次试这些词：`配送`、`派送`、`订单配送`、`送达`、`骑手`
3. 挑一个语义最接近「您的订单已由骑手取走，正在配送中」的模板。优先级：
   - 第一优先：模板名含「配送」且关键词里有 **订单编号 / 配送状态 / 预计送达时间**
   - 第二优先：模板名含「订单状态变更」「订单进度」
4. 点「选用」→ 在关键词列表里**按下表勾选**（勾选顺序决定字段编号，不同模板可选项不一样，按有什么勾什么）：

| 想传的内容 | 优先勾这些关键词 | 备选 |
|---|---|---|
| 订单编号 | 订单编号 / 订单号 | 订单信息 |
| 配送方式或状态 | 配送状态 / 订单状态 / 配送方式 | 温馨提示 |
| 骑手或商家联系方式 | 配送员电话 / 联系电话 | 服务电话 |
| 预计送达 | 预计送达时间 / 送达时间 | 配送时间 |

   > 关键词最多勾 5 个，**不够选就少勾**，能拿到「订单编号 + 一个状态类 + 一个时间类」就够用。

5. 「场景说明」填（可直接复制）：

```
顾客在小程序下单同城配送的凉菜后，骑手到店取餐并出发配送时，向该顾客推送本条通知，
告知订单已开始配送及预计送达时间，方便顾客留意收货。仅向本人下单的顾客发送，不做营销推广。
```

6. 提交 → 回到 **我的模板**，把这一条的 **模板 ID** 复制下来
7. 点开该模板，把每个关键词对应的**字段名**抄下来（形如 `character_string1`、`thing2`、`time4`、`phrase3`）

## ② 隐私保护指引：新增「收集你选择的位置信息」

### 现状
2026-09-02 已填过一版，勾了：收货地址、手机号、剪贴板。
本次要**新增一项**，因为同城配送要让顾客在地图上选收货位置。

### 操作步骤
1. mp.weixin.qq.com → 左侧 **管理 → 账号设置** → 页面顶部标签栏选 **服务内容声明** → **用户隐私保护指引** → 点「去完善」/「更新」

   > 旧版菜单叫「设置 → 基本设置」，新版已并入「管理 → 账号设置」。
   > 备用入口：`管理 → 版本管理 → 提交代码审核` 的信息填写页也能填同一份指引（提审时才走）。
2. 在「开发者处理的信息」清单里，找到并**勾选**：

   > **收集你选择的位置信息**

   ⚠️ 注意区分两个相似项，**只勾下面这个**：
   | 选项 | 对应接口 | 我们要不要 |
   |---|---|---|
   | 收集你的位置信息 | `wx.getLocation`（自动读取实时定位） | ❌ **不勾** |
   | **收集你选择的位置信息** | `wx.chooseLocation`（用户自己在地图上点） | ✅ **勾** |

   只勾后者的好处：顾客感受更好（是他自己点的，不是被偷偷定位），接口申请通过率也高得多。

3. 用途说明填（可直接复制）：

```
用于同城配送服务：顾客在填写收货地址时于地图上选择收货位置，
我们据此计算配送距离、判断是否在配送范围内、计算配送费，并将该位置提供给配送服务商用于骑手送达。
```

4. 已勾的其余项保持不变（收货地址、手机号、剪贴板）
5. 「开发者联系方式」确认是 `15309003232` / `835804187@qq.com`
6. 保存提交

已改为第二档「本小程序处理了用户信息」并勾选四项：**地址 / 手机号 / 选择的位置信息 / 剪切板**。
（不勾「位置信息」——那是未申请的 `wx.getLocation`；不勾「用户信息（微信昵称头像）」——登录只取 OpenID。）

同页其余必填项：
- **4.2 联系方式**：电话 `15309003232` + 邮箱 `835804187@qq.com`（不填则第 8 节报红）
- **5.1 存储期限**：保持「承诺为实现处理目的所必要的最短时间」，不要选固定天数——订单与地址因售后、对账、税务需长期留存，写死天数等于给自己挖坑
- **6.2 变更告知方式**：`小程序内弹窗`

**第 7.1 条是不可改的固定条款**：「不会主动共享或转让你的信息至任何第三方，如存在确需共享时…应当征得单独同意」。
同城配送必然要把收货信息交给快递100 与骑手，因此合规路径是在**我们自己的隐私政策全文**里具名披露 +

## ③ 地理位置接口申请 —— ✅ 已完成（2026-09-03）

### 开通了哪两个、为什么不开其余的

| 接口 | 状态 | 说明 |
|---|---|---|
| `wx.chooseAddress` | ✅ 已开通 | 「导入微信收货地址」用，修复既有失效功能 |
| `wx.chooseLocation` | ✅ 已开通 | 同城配送地图选点，核心 |
| `wx.getLocation` | ❌ 未申请 | "自动读取实时位置"，开放范围窄、[社区驳回案例](https://developers.weixin.qq.com/community/develop/doc/0000c2ead50158047ce1cf6c26b800)多为它；门店坐标改用地图选点，还能避开室内 GPS 漂移几十米导致运费算错 |
| `wx.choosePoi` / `getFuzzyLocation` | ❌ 未申请 | 前者 chooseLocation 已覆盖；后者精度不足以算配送费 |
| `onLocationChange` / `startLocationUpdate` 系列 | 无权限 | 持续定位，本业务不需要 |

> 提交时**没有用右上角「批量开通」**：一次提交多个接口，任一理由不充分会连累整批。

### 实际提交的申请理由（留档，日后新增接口可参照写法）

`wx.chooseLocation`（约 258 字）：

```
本店为自贡市实体凉菜熟食门店，已上传营业执照与食品经营许可证，现开通同城配送。顾客在「新增收货地址」页点击「在地图上选择收货位置」，调用 wx.chooseLocation 由顾客自行在地图上选点。

必要性：凉菜为短保质期即时配送商品，仅凭文字地址无法确定与门店的实际距离，会出现超范围仍下单、配送费算错、骑手找不到楼栋。取得坐标后用于：计算与门店距离并判断是否在配送范围内；按距离计算配送费并在下单前展示；提供给第三方即时配送服务商供骑手导航送达。

位置仅在顾客主动点击选点后获取，不做静默定位与轨迹追踪，已在隐私保护指引中勾选「收集你选择的位置信息」。
```

写法上三段各有分工：第一段交代"在哪个页面、点哪个按钮触发"；第二段回答审核员真正要判断的"为什么文字地址不够"；第三段堵住隐私顾虑。

`wx.chooseAddress` 的理由同构，把"需要坐标"换成"中老年顾客手输地址易漏写楼栋单元、导致配送失败与餐品报废"。

### 代码侧配套（已完成）
`apps/miniapp/app.json` 已加：
```json
"requiredPrivateInfos": ["chooseLocation"],
"permission": { "scope.userLocation": { "desc": "在地图选择收货地址或门店位置，用于计算同城配送距离与配送费" } }

> ⚠️ **`desc` 上限 30 字**（含标点）。超了会在**上传体验版时**报
> `80058 desc of scope.userLocation exceeds 30`——不是提审才报，是上传就上不去。
> 2026-09-06 踩过一次：有人往这句里加了「或设置门店位置」变成 32 字，体验版直接传不上。
> 改文案时先数字数：`python3 -c "print(len('…'))"`。
> 两个用途都必须提到：顾客选收货地址（`pages/address/edit.js`）与店主设门店坐标（`pages/merchant/index.js`），
> 少写一个与「隐私与位置能力一致性检查」（release-checklist §2.4b）对不上。
```
缺这段声明时调用会直接失败，**接口审核通过并不等于代码能跑**。
