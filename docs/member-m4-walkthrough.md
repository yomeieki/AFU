# 会员 M4 走查清单（微信开发者工具 + 预览台）

> M4 的验收方式。**每一项都要在开发者工具里真点一遍**，不是读代码确认。
> 预览台（`npm run preview:miniapp`）只做视觉近似，不能替代这份清单——
> 它不跑 js，点不动、也拿不到真实数据。
>
> 打勾时顺手截一张图。截图不是仪式：M3 那一轮就是靠截图发现「赠品页只要有一条
> 数据就白屏」的——类型写错了 `ON_SHELF`，tsc 拦不住，只有画面会告诉你。

## 2. 五个会员页 × 四态

每一页都要看到这四种画面。**「加载失败」和「暂无数据」必须长得不一样**——
接口挂了显示成「暂无优惠券」，顾客和店主都会当成真的没有。

| 页面 | 未登录 | 加载中 | 加载失败 | 空数据 |
|---|---|---|---|---|
| 会员中心 | ☐ | ☐ | ☐ | ☐ |
| 积分商城 | ☐ | ☐ | ☐ | ☐ |
| 我的券 | ☐ | ☐ | ☐ | ☐ |
| 领券中心 | ☐ | ☐ | ☐ | ☐ |
| 积分明细 | ☐ | ☐ | ☐ | ☐ |

制造「加载失败」的办法：把后端停掉再进页面，或在 Network 面板里把对应请求改成失败。

## 7. 邮寄结算页 `pages/order/confirm`

- [ ] 优惠卡出现在备注与金额区之间
- [ ] 默认自动选中面额最大的可用券（M4 D2 默认）
- [ ] 弹层里不可用的券**也列出来**且灰掉，并写明原因（未达门槛/仅限同城…）
- [ ] 选「不使用优惠券」→ 合计恢复

- [ ] 积分不够时点加号 → toast「积分不足」，数量不变

- [ ] 提交后订单详情里的实付 = 结算页显示的合计

- [ ] `metaFailed`（把 `/orders/meta` 打挂）与 `belowMinOrder` 两条既有拦截行为**没变**

## 8. 同城结算页 `pages/local/confirm`（谨慎区）

这条链路上有报价凭证，改错就是每单漏钱。六个降级分支逐条看：

- [ ] 正常：合计 = 商品小计 − 券 + 配送费
- [ ] 报价失败（把 `/local/quote` 打挂）→ 底部显示「待重新计算」，**合计不显示**，
      优惠组件 `disabled`
- [ ] 限流重试（连点几次触发 42901）→ 3 秒后自动重试，**优惠选择没丢**
- [ ] 超出配送范围 → 合计仍然不显示
- [ ] 非营业时间 → 同上
- [ ] 未达起送 → 同上（起送线按**券前**小计判）
- [ ] 配送费变化（42227/42239）→ 重新报价，优惠不丢
- [ ] 提交按钮文案 `提交订单 ¥X` 跟着优惠变
- [ ] 提交后实付 = 页面显示的合计
